# MisakaNetwork 0.1.1

日期：2026-10-24。构建号：2。内嵌 biliTickerBuy：2.15.17。

交付状态：0.1.1+2 本地 macOS arm64/x64 安装包已构建并核验，内含同版本 Linux/macOS 四平台 Sisters 完整离线部署包。未创建 Git Tag、远程 Release 或执行远程 CI。

## 本次变更

- LastOrder 在启动、每五分钟及查询场次/分发前检查账号登录状态。明确失效后清除钥匙串 Cookie 并引导重新扫码；断网、超时、限流等未知状态保留凭据并阻止新分发。
- 重新登录核对平台验证的 UID，更新原账号 Cookie 并保留任务选择。任务配置不存 Cookie 副本，执行时读取当前账号凭据。
- 完善钥匙串失败回报、删除回读验证和重试；防止旧检查结果覆盖新登录、并发保存丢失状态或分发已被更新的凭据。
- 删除不存在的凭据视为成功，避免 macOS 钥匙串插件在重复删除时误报权限错误；真实读写与删除错误仍会回报，应用沙盒保持启用。
- Sisters 与部署 helper 要求相同平台版本的 bridge，避免新版服务误用旧运行时。
- 发行检查核对应用 Info.plist 版本和构建号、四份内嵌部署包版本/平台/架构、字节数、SHA-256 及其独立校验文件，并扫描环境隐私信息。
- 修复 CI 合并平台产物后缺少总清单的问题，校验全部四份部署包后原子生成 `bundles.json`；缺包、混合版本或校验和不符时拒绝继续。

## 研发规范与升级

**1.0.0 前全部属于早期研发版本，优先采用更优实现，不受历史研发版本兼容性约束。** 该规范已记录到根目录 `AGENTS.md` 与发布文档。

0.1.1 使用严格 schema 2：账号必须具备平台验证的 UID，元数据保存为 `state-v2.json`，钥匙串条目使用 `v2.` 前缀。0.1.0 的配置和凭据保留原样，不读取、不迁移。升级后需要：

1. 先处理旧版正在运行的任务；新版不会接管旧任务记录。
2. 重新添加机器连接，并使用新版离线包重新部署 Sisters。
3. 重新登录账号并创建任务。

同一账号在 0.1.1 内重新登录可保留任务配置，但已提交到 Sisters 的执行不会热更新 Cookie，也不会自动重启；已有任务 ID 携带不同凭据重提会被拒绝，需要新建任务分发。
