## 变更

- LastOrder 新增 Windows 10+ x64 原生应用入口、Windows 安全存储、用户私有文件 DACL 与子进程退出清理。
- LastOrder 新增 Android 16（API 36）arm64/x64 入口，内嵌 Python 客户端与 Go JNI，复用账号登录、场次配置、SSH 部署和 mTLS 任务分发。
- 手机采用底部导航、窄屏卡片和任务操作布局；软键盘显示时对话框可滚动，回到前台刷新机器和账号状态。
- 统一五种 LastOrder 目标的打包与检查流程，所有完整应用内含四种 Linux/macOS Sisters 部署包；增加运行时版本清单，拒绝旧版本缓存。
- Android 禁止备份与明文 HTTP，安全存储失败不自动清空凭据；JNI 与文件权限接口限制到应用私有目录。

## 安装已生成的测试包

Android 设备必须运行 Android 16 或更新版本。通常选择 arm64 APK；x64 仅用于对应架构设备或模拟器。将 APK 传到设备后通过系统安装器安装，必要时授权所用文件管理器安装未知应用。不要在 Android 15 或更早版本安装；测试签名仅供验证，正式签名更换后不能直接覆盖升级。

macOS 按芯片架构选择 ZIP，解压后将 `LastOrder.app` 放入应用程序目录。两种包均保留沙盒、采用 ad-hoc 签名，未 Developer ID 签名与公证。

Windows 的源码、完整离线打包脚本、原生测试与 CI 已准备好，但没有生成可运行安装包。取得 Windows 构建环境后，按 [Windows 构建步骤](../打包与发布.md#windows-与-android-完整构建) 构建与原生验证，补齐第五份产物后才能完成统一发布。

## 升级影响与边界

- 0.1.1 的 schema 2 存储继续使用；同一平台、相同应用身份可读取既有状态。0.1.0 数据仍不迁移，需重新配置。新平台安装需重新登录与添加机器，不自动跨设备复制 Cookie 或 CA。
- 所有机器需要重新部署内嵌 0.1.5 Sisters；重部署会结束正在运行的任务，更新前请先停止或等待完成。
- Android 测试签名不可视为正式发行密钥；切换签名可能需要卸载重装、重新登录与部署。Android 后台同步不保证常驻，远程已启动任务不受应用前后台影响。
- Sisters 仍只提供 Linux/macOS x64/arm64；Windows Sisters 未实现。跨节点自动取消、任务重启恢复、证书自动续期及自动付款仍不提供。

实现与构建细节见 [Windows 与 Android](../LastOrder/Windows与Android.md) 和 [打包与发布](../打包与发布.md)。
