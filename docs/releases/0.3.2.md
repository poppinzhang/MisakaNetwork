## 本版改动

- **Android 内嵌运行时依赖与资源清理修复**：
  - 修复 Android 读取演出、购票人和地址时缺少 HTTPX / HTTP/2 纯 Python 依赖的问题，将与桌面一致版本的依赖锁定在 `runtime/requirements-android.lock`；升级运行时自检，使其离线构造真实标准 HTTP/2 客户端链路。
  - Android 查询只协商可解码的 `gzip, deflate`，避免上游默认声明 Brotli / Zstandard 却未携带解码器；每次内嵌调用独立初始化并关闭上游 HTTP 连接、数据库和临时状态并恢复环境，覆盖连续调用与异常清理。
- **扫码登录窗口失去焦点（`inactive`）阻塞修复**：
  - 修复 `0.3.1` 扫码窗口仅在 `resumed` 下自动生成、检测和保存导致的阻塞问题：Android 在应用仍可见但由分屏或系统/第三方悬浮窗持有输入焦点时报告 `inactive`，打开窗口会持续停在「正在生成登录二维码…」且禁用「重新生成二维码」。
  - 现按可见性处理：`resumed` 与 `inactive` 照常生成、检测和保存，仅 `hidden`/`paused`/`detached` 暂停并在恢复可见后立即检查一次；点击「重新生成二维码」「重试连接」「重试保存」、切换登录方式或提交 Cookie 均视为窗口可见，桌面窗口失焦但可见时同样继续检测。
- **回归测试与静态校验补强**：
  - 补充真实引擎客户端链路、标准 TLS 证书与主机名验证、原生二维码生成与配置回归；新增 Android API 36 x86_64 模拟器 CI 校验与 APK Python 模块、锁定依赖版本、CA 及 16 KB ELF/ZIP 对齐静态校验。
  - 复核并维持固定上游 `biliTickerBuy v2.15.18`（`227ebf73f5af3eec0019984a7cbcb722977453e8`）、标准 HTTPS 验证、内存 Cookie、空通知配置及无 Web UI 安全约束。
- **统一版本与全平台重打包**：
  - 统一递增项目版本为 `0.3.2+12`（Android `arm64` / `amd64` 的 `versionCode` 分别为 `2012` / `4012`），携带更新后的四平台离线 Sisters 运行时与管理端重新打包。

## 升级与使用注意

- **Sisters 重新部署**：更新至 `0.3.2` 管理端后，须将受控机器上的 Sisters 重新部署为 `0.3.2`，防止 helper/runtime 版本校验拒绝旧包；重新部署会中止该节点正在运行的任务，请在无活跃抢票任务时操作。
- **Android 覆盖安装**：`0.3.2+12` 使用同一长期发布密钥签名且构建号高于 `0.3.1+11`（`versionCode` 由 `2011`/`4011` 升至 `2012`/`4012`），可直接覆盖升级同签名正式版（测试签名 APK 需先卸载）。
- **macOS 钥匙串与数据目录**：继续使用 `macos-vault-v1` 独立加密存储，与 `0.3.1` 与 `0.3.0` 目录兼容；因延续 ad-hoc 签名，首次打开新版访问主密钥时系统仍可能要求确认钥匙串权限。
