## 本版改动

- **复制任务**：任务卡片新增「复制任务」。未分发和已分发的任务都可以复制。原卡片后出现一张同名的未分发副本，沿用账号、场次、票档、购票人、开售时间和请求间隔，使用新的任务 ID 和独立加密配置，分发记录为空，可单独编辑和分发。
- **编辑未分发任务**：「账号与任务」里尚未分发的任务可以「编辑任务」，修改账号、同一演出的场次与票档、开售时间、抢票请求间隔和购票人。切换账号后需要重新选择该账号的购票人。已有分发记录的任务，包括已结束的记录，保留原配置。
- **新建任务**：直接显示演出名称。去掉单独的日期输入框；输入演出 ID 或会员购链接后即可选择票档。演出提供日历场次时，可从平台给出的日期中选择，也可以使用已有的默认场次。开售时间默认取所选票档的起售时间，可在日历中选择北京时间的日期、时、分、秒；清除后，机器收到任务即开始。
- **新任务请求间隔**：默认从 1000 毫秒改为 500 毫秒，范围仍是 100–60000 的整数。已保存的任务沿用原间隔。省略间隔时，运行时等待 500 毫秒。每轮下单尝试上限仍固定为 40。
- **云购买中断后的卡片**：腾讯云、阿里云和火山引擎在创建结果未知时，按原购买记录有限次自动查询。一直查不到实例时，可以确认「删除本地卡片」，之后从该厂商的凭证页恢复。查询找回实例时卡片会自动出现。清理只影响本机列表；云端资源仍可能计费，原购买记录和凭证保护继续保留。
- **统一版本与全平台重打包**：五种 LastOrder 与五种 Sisters 目标统一为 `0.4.2`；Android `arm64` / `amd64` 的 `versionCode` 分别为 `2015` / `4015`。Linux/macOS/Windows Sisters 的部署方式没有单独的功能变化，仍按统一发布约定重新构建。

本版不升级 biliTickerBuy 的版本、固定提交、导入白名单、锁定依赖或嵌入适配。运行时除统一版本号外，只改变省略间隔时的默认等待。标准 HTTPS 验证、`standard` 下单策略、空第三方通知配置与禁止 Web UI/Gradio 的约束保持不变。间隔复核见 [biliTickerBuy 运行时](../biliTickerBuy运行时.md#默认请求间隔调整复核2026-11-18)。

## 升级与使用注意

- **重新部署所有 Sisters**：安装 0.4.2 管理端后，在没有活跃抢票任务时将所有受控机器（含 Linux、macOS 和 Windows）重新部署为 `0.4.2`，防止 helper/runtime 版本校验拒绝旧包。重部署会停止该节点正在运行的任务，并清空内存任务历史和付款入口；操作前先核对订单。
- **数据无需重建**：账号、已保存的任务配置、云凭据与资源记录、macOS `macos-vault-v1` 存储格式均与 0.4.1 相同，无需重新登录或重建任务。已分发过的任务不能直接改配置；需要调整时使用「复制任务」，再编辑副本。
- **新任务间隔**：0.4.2 新建任务默认 500 毫秒。0.4.1 及更早保存的任务继续使用原来的间隔。
- **云卡片清理**：删除「创建结果待核实」卡片只从本机列表隐藏，不会释放云服务器，也不会解除凭证保护。删除前请在云厂商控制台核对服务器和账单。
- **Android 覆盖安装**：沿用长期发布签名密钥，`versionCode` 从 `2014`/`4014` 递增为 `2015`/`4015`，可覆盖同签名正式版；测试签名 APK 需先卸载。Android 仍只管理任务，不在手机本机运行 Sisters。
- **macOS 与 Windows 签名**：macOS 仍为 ad-hoc 签名、未公证，首次打开新版访问主密钥时可能需要钥匙串授权；Windows 包仍不含 Authenticode 签名。
- **持续运行与订单核对**：关闭 LastOrder 不会停止远程 Sisters；取消和重新部署不能撤销票务平台已创建的订单，仍需在官方平台核对并付款。
