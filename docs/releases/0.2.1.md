CI 使用目标系统/架构构建原生运行时，每份 LastOrder 均携带同版本 Linux/macOS arm64/x64 四种 Sisters 离线部署包。源码和离线模拟测试不代表真实业务验收；最终 CI 结果也不能替代设备业务验证。

首次云端尝试在运行时隐私检查阶段停止：官方 Python 和 wheel 中的公共 runner 构建路径与通用 runner 主目录标记重合。第二次尝试确认 Linux 上游 Python 同样携带公共临时根目录路径。已调整 CI 检查范围为本次仓库路径，并为 Android 加查实际签名文件路径，继续扫描原生文件与压缩代码；本地默认检查不变。该次失败未产生公开 Release，修复后重新运行完整平台构建，四种 Sisters 部署包已通过第三轮检查。第三轮 Android SDK 初始化请求了已移除的 `tools` 包，已改为显式安装 `platform-tools`，既定 SDK、build-tools 和 NDK 版本不变；完整应用构建继续验证。macOS 原生应用编译后暴露 `lipo` 参数顺序兼容问题，已改为输入文件在前、架构检查参数在后，保留严格架构检查。

## 升级影响与边界

- 升级前核对已有订单，停止或等待现有任务完成。升级 LastOrder 后重新部署全部 Sisters；重新部署会中断任务，不自动恢复。
- 现有 schema 2 配置、主题和显式端口继续使用，桌面端不因本次升级要求重新登录。新设备仍需添加机器并登录。
- Android 本版首次使用长期发布密钥，与此前测试签名不同，旧测试 APK 无法直接覆盖升级。先核对订单和任务，再卸载旧版、安装新版；卸载会删除本地数据，需要重新添加机器、登录账号与创建任务。今后沿用同一发布密钥。
- 从 0.1.0 升级需重新配置；更早 Android 包的缓存处理见 [0.1.6 升级记录](0.1.6.md#升级影响与边界)。卸载重装后无需额外保留或迁移旧缓存。
- macOS 未经 Apple 公证，Windows 未签名；系统可能提示风险或要求确认。GitHub 正式 Release 标识不改变签名状态或业务验证范围。
- 各机器独立执行，一台成功后不会自动取消其他机器；关闭管理台、删除本地记录不会停止远程任务。
- Windows Sisters、跨节点自动取消、任务重启恢复、证书自动续期和自动付款仍未实现；Android 后台同步不保证常驻。
