## 本版改动

- **Windows 10+ x64 Sisters**：提供前台运行与 SCM 后台服务；服务使用专用虚拟账户 `NT SERVICE\MisakaSisters` 和私有临时目录，程序、配置与证书目录限制访问，任务通过 Windows Job Object 管理并清理整个进程树。
- **Windows SSH 离线部署**：LastOrder 使用管理员 OpenSSH 会话上传内嵌包，通过编码 PowerShell 完成目录准备、DACL、自检、SCM 服务安装与切换；失败时恢复旧服务，首次失败时删除新服务。保留首次连接 TOFU、后续指纹核对、双向 TLS 和部署后直连检查。
- **五种离线 Sisters 包**：新增 `windows-amd64`，与 Linux/macOS 的 arm64/x64 一并内嵌到每份 LastOrder；Windows 运行时原生构建，归档校验增加 Windows x64 PE、路径与版本检查，Android 资源提取同步覆盖第五种包。
- **Windows 原生验证**：CI 增加全量 Go race/vet、PowerShell 脚本解析、隔离 SCM 集成测试以及真实 Windows runtime 与 Sisters 的离线 mTLS 冒烟；覆盖虚拟服务账户、DACL、特殊路径、Junction 拒绝、失败恢复和服务删除。
- **统一版本与全平台重打包**：所有五种 LastOrder 与五种 Sisters 目标统一为 `0.4.0`；Android `arm64` / `amd64` 的 `versionCode` 分别为 `2013` / `4013`。本次不升级 biliTickerBuy 的版本、固定提交、导入白名单或锁定依赖，标准 HTTPS 验证、`standard` 下单策略、空第三方通知配置与禁止 Web UI/Gradio 的约束保持不变。

具体准备、服务权限与失败语义见 [Windows Sisters](../Sisters/Windows支持.md)；运行时约束与复核范围见 [biliTickerBuy 运行时](../biliTickerBuy运行时.md)。

## 升级与使用注意

- **重新部署所有 Sisters**：升级至 `0.4.0` 管理端后，在没有活跃抢票任务时将所有受控机器重新部署为 `0.4.0`，防止 helper/runtime 版本校验拒绝旧包。重部署会停止该节点正在运行的任务，并清空内存任务历史和付款入口；操作前先核对订单。
- **Windows 机器准备**：管理员需提前启用兼容的 OpenSSH Server、配置管理员 SSH 登录与所需端口。LastOrder 不安装 SSH、不弹出远程 UAC，也不修改防火墙；具体步骤见 [机器准备](../Sisters/Windows支持.md#机器准备)。三家公有云创建模板仍只支持 Linux；Windows 使用已有机器的 SSH 部署入口。
- **Android 覆盖安装**：本版沿用长期发布签名密钥，`versionCode` 从 `2012`/`4012` 递增为 `2013`/`4013`，正式产物通过签名核验后可覆盖同签名正式版；测试签名 APK 需先卸载。Android 仍只管理任务，不在手机本机运行 Sisters。
- **macOS 与已有数据**：延续 `macos-vault-v1` 独立加密存储，与 0.3.0–0.3.2 保持相同数据格式；ad-hoc 签名未改变，首次打开新版访问主密钥时仍可能需要钥匙串授权。由 0.2.3 或更早 macOS 版本升级时，仍须按 [macOS 加密存储说明](../LastOrder/macOS加密存储.md) 处理旧任务与云资源，再重新添加机器、登录账号和创建任务。
- **持续运行与订单核对**：关闭 LastOrder 不会停止远程 Sisters，机器睡眠、关机或重启会中断任务；服务重新启动不恢复原任务。取消和重新部署不能撤销票务平台已创建的订单，仍需在官方平台核对并付款。
