## 本版改动

- **购票人证件类型标注**：创建和编辑抢票任务时，「购票人」列表在姓名后标注证件类型（例如「张三（护照）」），方便区分同名购票人。按平台返回的 `id_type` 支持显示身份证、护照、港澳居民来往内地通行证、台湾居民来往大陆通行证和外国人永久居留身份证；缺失或无法识别的取值显示「证件类型未知」，不会猜测。本项仅改变 LastOrder 界面显示，提交给运行时的购票人记录、内嵌运行时和 Sisters 均不变。
- **空白联系人自动填写**：创建抢票任务时，若「联系人」和「联系电话」均为空白，勾选购票人会自动填入该购票人的姓名和电话。任一栏已有内容（包括先前自动填入的内容）后，再勾选其他购票人不再改动；取消勾选不会清空，两栏仍可随时手动修改。购票人没有电话或电话为部分隐藏（如 `138****1234`）时仅填入姓名，电话需手动补填。编辑任务沿用原联系人，不自动填写。尚未用真实账号核对平台返回的购票人电话是否完整。
- **统一版本与全平台重打包**：五种 LastOrder 与五种 Sisters 目标统一为 `0.4.3`；Android `arm64` / `amd64` 的 `versionCode` 分别为 `2016` / `4016`。Linux/macOS/Windows Sisters 与内嵌运行时没有功能变化，仍按统一发布约定重新构建。

本版不升级 biliTickerBuy 的版本、固定提交、导入白名单、锁定依赖、嵌入适配或运行参数，运行时仅更新统一版本号。标准 HTTPS 验证、`standard` 下单策略、默认请求间隔（500 毫秒）、空第三方通知配置与禁止 Web UI/Gradio 的约束保持不变。复核见 [biliTickerBuy 运行时](../biliTickerBuy运行时.md#043-统一版本复核2026-11-19)。

## 升级与使用注意

- **重新部署所有 Sisters**：安装 0.4.3 管理端后，在没有活跃抢票任务时将所有受控机器（含 Linux、macOS 和 Windows）重新部署为 `0.4.3`，防止 helper/runtime 版本校验拒绝旧包。重部署会停止该节点正在运行的任务，并清空内存任务历史和付款入口；操作前先核对订单。
- **数据无需重建**：账号、已保存的任务配置、云凭据与资源记录、macOS `macos-vault-v1` 存储格式均与 0.4.2 相同，无需重新登录或重建任务。
- **Android 覆盖安装**：沿用长期发布签名密钥，`versionCode` 从 `2015`/`4015` 递增为 `2016`/`4016`，可覆盖同签名正式版；测试签名 APK 需先卸载。Android 仍只管理任务，不在手机本机运行 Sisters。
- **macOS 与 Windows 签名**：macOS 仍为 ad-hoc 签名、未公证，首次打开新版访问主密钥时可能需要钥匙串授权；Windows 包仍不含 Authenticode 签名。
- **持续运行与订单核对**：关闭 LastOrder 不会停止远程 Sisters；取消和重新部署不能撤销票务平台已创建的订单，仍需在官方平台核对并付款。
