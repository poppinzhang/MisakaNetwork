# 离线包端到端冒烟验证

`cmd/misaka-smoke` 使用打包后的 Sisters 和真正的 biliTickerBuy runtime 验证服务到引擎的连接，不调用模拟 runner。工具只接受可执行文件路径、期望平台和测试超时，不提供 Cookie、场次、任务配置或目标服务地址参数。

工具在独立临时目录生成短期使用的测试 CA、服务端和客户端证书，以随机回环端口启动一个临时 Sisters。所有任务使用代码中固定的空配置 `{}` 与明确无效的 synthetic Cookie；提交前再次检查该约束。真实 runtime 必须在本地配置校验阶段失败，不能访问票务平台创建订单。

验证项目包括：

1. 双向 TLS 连接与实际 runtime readiness、项目版本、biliTickerBuy 版本和目标架构。
2. 仅信任 CA、未提供客户端证书的连接被拒绝。
3. 固定非法配置进入队列后最终返回 `FAILED`，绝不作为成功处理。
4. 状态回报不泄漏写入的 Cookie 或临时目录。
5. 重试同一任务 ID 与相同载荷不会重复执行；不同载荷使用相同 ID 被拒绝。
6. 取消已结束任务不修改结果；取消不存在的任务返回 `NotFound`。

```sh
go build -trimpath -o .build/misaka-smoke ./cmd/misaka-smoke
.build/misaka-smoke --sisters <解包目录>/sisters \
  --runtime <解包目录>/runtime/misaka-runtime \
  --expect-platform darwin/arm64
```

Linux 可交叉编译测试工具，然后在对应 Ubuntu 24.04 同代系统或容器中执行：

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath \
  -o .build/misaka-smoke-linux-amd64 ./cmd/misaka-smoke
```

arm64 对应 `GOARCH=arm64`，期望平台使用 `linux/arm64`。macOS Intel 对应 `darwin/amd64`，可在具备 Rosetta 的 Apple Silicon 主机上验证 Intel 包启动，但不能替代真实 Intel 硬件验收。

0.4.0 源码的 Windows x64 包使用 `sisters.exe`、`runtime/misaka-runtime.exe` 和 `--expect-platform windows/amd64`，在原生 Windows 执行同一工具。进程清理采用 Windows 机制，不依赖 Unix 执行权限位或 `SIGINT`。此冒烟启动前台服务，不替代 SCM 安装、自启动或 SSH 部署/回滚验收；详见 [Windows Sisters](Sisters/Windows支持.md)。

输出为一行 JSON，只包含通过状态、版本、平台和检查项目，不包含监听地址、证书、凭据、机器名或个人路径。默认整个验证最长 60 秒，可通过 `--timeout` 调整为不超过 5 分钟。结束或收到可处理的中断时，工具关闭临时 Sisters，并清理证书和配置目录；Sisters 负责取消自己的运行时子进程。

这项检查证明打包产物能够加载引擎、通过受认证网络提交任务并处理真实校验失败。在线二维码登录、账号授权、真实场次下单与支付仍需独立验收，不能将离线检查结果描述为真实抢票成功。
