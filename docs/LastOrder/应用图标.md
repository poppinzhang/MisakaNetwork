# LastOrder 应用图标

macOS、Android、Windows 统一使用仓库中的 `LastOrder/assets/branding/LastOrder.png`。该文件为用户提供的 1254×1254 RGB PNG 原图；平台资源仅等比例缩小，保留完整构图与白色背景。

| 平台 | 资源位置（相对 `LastOrder/`） | 像素尺寸 |
| --- | --- | --- |
| macOS | `macos/Runner/Assets.xcassets/AppIcon.appiconset/app_icon_*.png` | 16、32、64、128、256、512、1024 |
| Android | `android/app/src/main/res/mipmap-*/ic_launcher.png` | mdpi 48、hdpi 72、xhdpi 96、xxhdpi 144、xxxhdpi 192 |
| Windows | `windows/runner/resources/app_icon.ico` | 16、24、32、48、64、128、256，单个 ICO 内含全部 PNG 帧 |

macOS 沿用 Xcode 的 `AppIcon` 资源集及 `Contents.json` 尺寸映射；Android 的 Manifest 沿用 `@mipmap/ic_launcher`，由启动器决定最终显示形状；Windows 的 `Runner.rc` 与窗口图标共用 `IDI_APP_ICON`。原图用于维护平台资源，无需加入 Flutter 的运行时 assets 清单。

替换原图时，同步重新生成表中全部平台资源，并检查 PNG 尺寸、资源引用和 ICO 各帧。PNG 可在 macOS 使用系统 `sips -z <尺寸> <尺寸> <原图> --out <目标>` 缩放；Windows ICO 需封装表中全部尺寸，不能直接将 PNG 改名。图标资源已纳入源码，正常构建无需额外安装图标生成依赖。

新图标纳入 0.2.1，构建状态见[交付记录](../releases/0.2.1.md)；既有发行包保持原样。发布按[打包与发布](../打包与发布.md)统一构建全部支持的平台与架构。

图标资源单独验证记录（2026-11-12）：原图与输入文件逐字节一致；全部 PNG 及 ICO 内嵌帧通过尺寸、CRC、像素数据解压与结构检查，三平台资源引用完整。macOS `actool` 成功编译 `AppIcon.icns`，Android SDK 36 的 AAPT2 成功编译全部五种密度图标；已查看缩小后的图片。上述资源验证未构建完整应用包，也未执行 Windows 原生编译或设备安装验收。
