# macOS 本地测试环境清理

`scripts/clean_lastorder_macos.py` 用于用户主动丢弃全部 LastOrder 本地测试资料。它不是资料损坏恢复工具；需要保留旧资料时，应按[macOS 加密存储](macOS加密存储.md)恢复匹配的密钥与文件，不执行本脚本。

## 使用

需要 Python 3.11+ 与可用的 Xcode Command Line Tools/Swift。使用当前登录用户，不使用 `sudo`。脚本与同目录的 `lastorder_keychain_cleanup.swift` 一起使用。

先停止或等待远端任务结束、核对订单，并确认不需要的云服务器已经释放。清理本地资料不会取消任务、撤销订单或停止计费；原云部署私钥与资源关联将丢失。然后完全退出 LastOrder；脚本发现当前用户仍有 `LastOrder`、`misakactl`、`misaka-runtime` 进程时停止，不自动结束进程。若本机另有 Sisters 使用同名运行时，也需先处理其任务并退出。

从仓库根目录执行只读预览：

```sh
python3 scripts/clean_lastorder_macos.py
```

确认列出的范围后，由用户手动执行：

```sh
python3 scripts/clean_lastorder_macos.py --apply
```

`--dry-run` 与不带参数相同。预览可能触发钥匙串权限提示，但不读取秘密值或删除资料；会在临时目录编译辅助器，结束后移除编译产物。脚本不会启动 LastOrder、调用云接口或修改系统设置。

## 范围与归属验证

- 清理 `io.misakanetwork.lastOrder` 沙盒的 `Data`，覆盖新旧元数据、`macos-vault-v1`、证书、导入凭据、偏好与缓存；保留容器根目录的 macOS 管理元数据。
- 清理同 bundle ID 的非沙盒 Application Support、Caches、Preferences、Saved Application State，以及当前用户系统临时目录下的同 bundle ID 专用目录。路径不存在时跳过。
- 新钥匙串只匹配 `MisakaNetwork.LastOrder.vault` 服务与 `macos.vault.master.v1` 账号。
- 原生存储集成测试残留按固定标签 `LastOrder synthetic storage test`、主密钥账号和 `MisakaNetwork.LastOrder.integration.<UUID>` 服务名共同匹配。
- 旧 `flutter_secure_storage_service` 是通用服务名，不能整组删除。脚本先从旧 `state.json`、`state-v2.json` 及其 `.tmp` 文件提取账号、任务 ID，生成精确键候选；不会读取或打印 Cookie、购票资料、云密钥或主密钥。未发布的旧云条目通过钥匙串 ACL 应用归属核对。
- 钥匙串辅助器只查询登录钥匙串中的属性和条目引用；对于无法用元数据识别的旧候选条目，核对 ACL 中现存应用的 `CFBundleIdentifier`。不以路径中包含 “LastOrder” 判断归属，不在查询中请求秘密数据。删除使用已经匹配的条目引用。
- 归属不明的旧候选条目导致整个清理在删除前停止，保留文件供人工核对。旧应用已移除、元数据丢失或钥匙串权限不足时，不能承诺自动清除孤立凭据；用户需要在钥匙串访问中核对。不能为覆盖历史残留而通配删除其他 Flutter 应用的记录。
- 路径自身或祖先包含符号链接时停止；数据目录内部的符号链接只删除链接，不遍历其目标。当前用户主目录取自系统用户记录，不信任 `HOME` 覆盖；不支持提权执行或替换清理根目录。

系统通用临时目录中的 `misaka-runtime-*` 可能由 Sisters 共用，不能只凭前缀证明属于 LastOrder；脚本不批量删除这些目录，也不清理通用的 `misaka-deployment-*`。如曾非沙盒运行，用户可另行核对它们的归属。应用本体、源码、构建产物、依赖缓存、原始 SSH 私钥、手动导出的 Cookie、其他目录的备份、其他用户与其他钥匙串不在范围内。

## 失败与重新开始

钥匙串枚举、权限或归属检查失败时，不开始删除数据文件；已开始删除后的错误不具备跨文件/钥匙串事务回滚能力，可能部分完成。脚本返回非零并提示，不会宣称完整重置。修复权限等问题后重试，期间不要打开 LastOrder，以免生成新资料与剩余资料混用。

较早脚本仅输出 `A keychain deletion failed`，丢失了系统返回的具体原因。当前版本输出失败的 API、`OSStatus` 数值、系统说明、失败序号和本轮删除调用成功数量；这些诊断不包含凭据值或账号标识。遇到授权/交互错误，先在钥匙串访问中确认登录钥匙串已解锁，再从本机终端重试并处理系统提示；不使用 `sudo`，也不批量放宽访问控制。

独立清理辅助器使用 `SecKeychainItemDelete` 删除已经完成归属核验的单个传统钥匙串引用，保持后续重新查询确认。Apple 的通用 `SecItemDelete` 传统实现包含调用应用身份检查，可能将与 LastOrder 不同的清理工具判为 `errSecInvalidOwnerEdit`；Apple 自带 `security delete-generic-password` 使用单条传统接口。依据：[Apple 通用删除实现](https://github.com/apple-oss-distributions/Security/blob/main/OSX/libsecurity_keychain/lib/SecItem.cpp#L1988-L2103)、[Apple 命令行工具实现](https://github.com/apple-oss-distributions/Security/blob/main/SecurityTool/macOS/keychain_find.c#L459-L502)。这解释了旧实现的适配问题，但由于旧脚本未记录错误码，不能断言每次旧报错均由该原因引起；当前接口仍受系统授权控制，脚本不修改 ACL。

成功后重新打开完整 LastOrder 测试包，重新登录、添加机器、创建任务及设置云凭据。新控制端 PKI 与云 SSH 密钥不会自动接管旧节点，需要重新部署或自行导入匹配证书。

## 验证边界

本轮 22 项离线回归通过，仅使用临时合成目录与模拟系统接口，核对路径限制、元数据提取、符号链接、预览、错误码透传、部分失败数量与失败保留文件。Swift 合成测试包含 31 个归属判断和 8 个删除返回状态用例，删除调用被模拟闭包替代，编译时禁用生产入口。不以此声称真实钥匙串枚举、系统授权、删除或完整重置已经实机验收。编写及修复脚本期间不执行用户环境的预览或清理，也不读取实际钥匙串条目。
