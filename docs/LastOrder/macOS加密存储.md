# macOS 单一主密钥加密存储（未发布）

本次仅调整 macOS 的 LastOrder 本地存储。已交付的 0.2.3 仍将每个账号和任务保存为独立钥匙串条目；源码中的新实现只在登录钥匙串保存一个应用主密钥，将账号 Cookie、任务购票资料、云凭据、云资源记录和云部署 SSH 密钥写入本地加密文件。Windows 加密存储和 Android Keystore 支持的存储路径保持不变。

## 授权与会话

`LocalStore` 为同一资料目录共用一个 `EncryptedVault` 实例。加载本地资料时先读取主密钥并验证密文，成功后才允许应用完成初始化；同时到达的请求共用同一解锁操作，本次应用进程内继续复用密钥。账号检查、任务分发、账号清理及云记录保存不再分别读取钥匙串条目。只缓存密钥，磁盘密文在每次操作时重新读取和校验，避免用旧的内存资料掩盖文件损坏或覆盖其他写入。

主密钥的系统读取失败也保留在本次会话中，自动检查不会不断重试授权。拒绝授权或钥匙串异常后，用户需要处理权限并重新打开应用再试；不将这种错误当作“没有保存过资料”，也不自动创建替代密钥。

此改动减少应用发起的钥匙串访问，不改变 macOS 的系统授权规则。当前打包仍使用 ad-hoc 签名；重新打包、系统锁定或权限变化仍可能触发确认，不能承诺所有情况下恰好一次或永不弹窗。输入的 Mac 登录密码由系统验证，LastOrder 不接收或保存它。

## 存储布局

macOS 在应用支持目录中的 `MisakaNetwork/macos-vault-v1` 下保存新资料；下面只使用逻辑目录，不记录个人机器路径。

| 位置 | 保存内容 |
| --- | --- |
| 登录钥匙串 | 服务 `MisakaNetwork.LastOrder.vault`，键 `macos.vault.master.v1`，标签 `LastOrder 本地资料加密密钥`；值为 Base64 编码的随机 32 字节主密钥 |
| `macos-vault-v1/secrets-v1.json` | 经认证的 AES-256-GCM 密文及版本、nonce、认证标签；不含明文记录名或敏感值 |
| `macos-vault-v1/state-v2.json` | 原有 schema 2 普通元数据：机器连接资料、账号名称与 UID、任务关联、主题等；不保存 Cookie、完整购票资料或云密钥 |
| 新根目录内的 PKI 与 `credentials` | 本机 mTLS 身份和导入证书、私钥副本，继续使用私有文件权限，不与旧根目录共用或互相清理 |

所有 `StateStore.readSecret/writeSecret/deleteSecret` 的 macOS 调用均经过同一个加密文件。普通 SSH 登录密码仍只在部署时的内存中使用，不持久化；付款内容继续遵循[付款码回显](../付款码回显.md)的内存生命周期，不因新增加密文件而持久化。

## 加密与文件写入

实现位于 `LastOrder/lib/src/encrypted_vault.dart`，使用 `cryptography` 包的 AES-256-GCM 实现，不自行实现加密算法。主密钥由安全随机数生成器产生；每次写入使用新的 12 字节 nonce 和 16 字节认证标签。固定附加认证数据为 UTF-8 编码的 `MisakaNetwork.LastOrder.secrets-v1.AES-256-GCM`，将密文绑定到本格式。

外层 JSON 只含 `version: 1`、Base64 `nonce`、`ciphertext` 和 `mac`。解密后的内容为记录名到字符串值的映射；任务值仍剔除 Cookie 副本。版本、字段类型、密钥、nonce 和标签长度均需校验；格式异常、密钥不匹配或认证失败不返回任何记录。

目录权限为 0700，密文、临时文件及锁文件权限为 0600。写入前检查目录和文件类型，拒绝符号链接或非普通文件。每次操作通过进程内按路径排队和系统文件锁串行执行；写操作在锁内读取最新密文、修改映射、加密后写入同目录临时文件，刷新并设置权限后原子替换目标。临时文件只包含密文，不写出明文中间文件。

首次建立存储时，仅在主密钥、密文、孤立临时密文与新目录内的元数据均不存在的情况下生成密钥并持久化空的加密映射。上述文件检查位于 vault 文件锁内：存在 `state-v2.json` 却缺少密文时，即使主密钥也丢失，仍拒绝生成空库；存在 `secrets-v1.json.tmp` 却缺少主文件时，保留临时密文并停止，避免覆盖最后一份可恢复资料。已有密文但主密钥丢失或无效、已有主密钥但密文缺失、初始化中断、损坏内容或权限失败均停止操作，不自动重新初始化。读写错误以不含敏感内容的提示回报；不得把密钥、Cookie、购票资料、云密钥或解密内容放入普通日志。

删除某条账号或任务记录会写入新的完整密文，不删除共享主密钥；不存在的记录可重复删除。调用方保留删除后的回读确认。加密和原子替换保障的是已保存资料的保密性、完整性与一致性，不提供备份恢复、历史密文防回滚或磁盘物理安全擦除保证。主密钥仅在应用进程内复用，关闭应用后下次访问重新读取。

## 首次初始化失败的人工恢复

主密钥写入成功、首次空密文写入失败时，下一次启动会按“已有密钥但缺少资料”拒绝继续。这可能发生在首次启动时磁盘空间不足或写入权限异常；应用没有自动重置入口，也不能仅凭错误提示判断原来没有资料。

仅限用户或管理员已独立确认这是**全新且从未成功使用的资料库，未保存过账号、任务、云凭据或云资源记录**时，可以进行以下开发阶段恢复：

1. 完全退出 LastOrder，先修复磁盘空间或文件权限问题。
2. 只移除本应用支持目录中的新 `MisakaNetwork/macos-vault-v1` 目录；保留旧 `MisakaNetwork` 根目录内其他内容。
3. 在“钥匙串访问”中精确核对服务 `MisakaNetwork.LastOrder.vault` 和账号键 `macos.vault.master.v1`，只移除这一条新主密钥。不要删除整个登录钥匙串、其他应用记录或旧的逐条凭据。
4. 重新打开 LastOrder，让它重新建立一套新的主密钥和空密文。

曾成功保存资料，或无法确认上述全新条件时，不使用此重建办法。应保留文件并恢复相互匹配的原主密钥、密文及元数据；不能通过删除主密钥或重建空文件解决既有资料库的错误。远端云资源或任务是否仍存在，需要通过原管理记录或对应平台另行核对。

## 不兼容升级与远端影响

按本次变更要求，不读取或迁移旧根目录、旧 `state-v2.json` 和逐条钥匙串记录，也不删除它们。新根目录中的证书清理只针对新目录，不触碰旧证书副本。Windows/Android 不切换目录，不受此次资料重建影响。

macOS 使用包含此改动的完整应用前后，需要执行以下步骤：

1. 在旧应用核对订单，并停止或等待已经分发的任务完成，包括排队和等待开售的任务。新资料目录没有旧执行账本，不能依赖新界面判断旧任务是否结束。
2. 若使用过未发布的公有云版本，先在旧应用或云厂商控制台核对服务器及网络资源，释放不再使用的资源并确认结果。新版本不会导入旧资源关联或恢复旧操作；关闭应用、换版本和本地记录消失都不会释放资源或停止计费。
3. 在新应用重新添加机器并完成部署，以安装新控制端信任的证书；自行管理节点也可通过“连接已部署的 Sisters”重新导入匹配的原证书。随后重新登录账号、创建任务、录入云凭据和设置偏好。

新资料目录会产生新的控制端 PKI 与云部署 SSH 密钥。原有 Sisters 不会自动信任新 PKI，既有云主机也不会自动接受新 SSH 公钥；不能把“重新输入云凭据”理解为已经接管旧主机。重新部署会中断远端任务，必须先完成上述任务核对。

本次不增加版本号或发布安装包，源码变更列于根目录 `CHANGELOG.md` 的 `unstaged`。公开安装入口和签名状态仍以 [0.2.3 交付记录](../releases/0.2.3.md)为准。
