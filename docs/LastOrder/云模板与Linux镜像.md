# 云模板与 Linux 镜像（未发布）

三家云厂商的模板配置工具已合并到独立的 `MisakaNetwork-config` 目录，与主项目分开维护，不随 LastOrder 打包。打开统一首页后先选择腾讯云、阿里云或火山引擎，再进入对应编辑页面。一个本地服务提供三家页面、只读选项查询与模板保存，厂商之间的 API 路由、校验器和目标文件隔离。

## 镜像选择

镜像列表不再限定 Ubuntu 24.04、官方公共镜像或特定发行版，也不按机型、架构、状态、磁盘映射自动隐藏条目。工具展示当前凭据在所选地域通过官方 API 能查询到的完整结果，保留名称、来源、系统、版本、架构、状态和容量等信息供管理员判断；仍可直接填写镜像 ID。

“完整”指 API 对该账号开放的查询范围，不表示全球镜像、所有付费市场商品或无权访问的私有镜像。不同厂商的来源接口及分页方式分别处理；不能在分页失败、响应不完整或达到处理上限后把局部结果显示成完整列表。选项查询不创建或购买资源，密钥不写入模板或持久化到网页存储。

腾讯云不传镜像过滤条件；阿里云使用所有状态，合并默认来源、市场和社区镜像；火山引擎查询全部已文档化状态，合并默认结果及公共、私有、共享来源，避免依赖未说明的默认来源覆盖范围。来源之间按镜像 ID 合并。接口依据：[腾讯云 DescribeImages](https://cloud.tencent.com/document/api/213/15715)、[阿里云 DescribeImages](https://help.aliyun.com/zh/ecs/developer-reference/api-ecs-2014-05-26-describeimages)、[火山引擎 DescribeImages](https://docs.volcengine.com/docs/ecs/describeimages-queriesimages?lang=zh)。

选择镜像与确认可运行是两个步骤。LastOrder 创建前不再按发行版名称或 Ubuntu 版本拒绝镜像，但仍核对选定 ID、可用状态、架构和系统盘约束；阿里云及火山引擎依据 API 系统类型确认 Linux。腾讯云镜像接口缺少独立 Linux 类型字段，只拒绝明确的非 Linux 元数据，不用发行版白名单猜测未知系统。最终 SSH 部署仍需识别为 Linux、x64/arm64 且 glibc 至少 2.39，并通过用户服务和内嵌运行时自检。

支持范围包括满足要求的其他 Linux 发行版以及更新 Ubuntu，不代表任何 Linux 镜像均可部署。现有 Linux 运行时基线仍为 glibc 2.39+、GTK 3.24，并需要 SSH、systemd 用户服务和 linger。部署已经显式检查系统/架构/glibc、linger，以及 Sisters 和内嵌运行时能否启动；没有单独执行 GTK 版本检查，也不把自检通过表述为全部系统依赖或真实抢票业务验收。低于 glibc 基线、使用 musl 或缺少用户服务条件的系统仍可能部署失败。

## 模板格式与登录账号

当前模板版本：腾讯云 `schemaVersion: 4`，阿里云和火山引擎 `schemaVersion: 2`。三家均新增顶层 `sshUsername`，`os` 改为管理员填写的系统显示名称，不再固定 `Ubuntu 24.04 LTS`。各厂商 `runInstances` 参数结构及计费、数量、公网、安全组和资源释放策略保持原有约束。

`sshUsername` 必须是 1–32 字符的 Linux 登录账号，以小写字母或下划线开头，后续可使用小写字母、数字、下划线和短横线。管理员应填写所选镜像实际允许原公钥登录的账号。该字段用于 SSH 连接，不会创建远程账号、轮流尝试账号或修改 SSH 配置；登录权限与公钥注入行为仍由镜像和云平台决定。阿里云支持的 `root` / `ecs-user` 使用对应镜像登录选项，其余自有账号须由镜像准备好。

腾讯云仅在模板登录账号为 `ubuntu` 时沿用已有的限定非交互 sudo linger 补救；其他账号不自动套用该命令。已有机器记录保存部署账号，发现账号改变时仍按既有规则停止，不能通过编辑模板在旧服务仍运行时静默换账号部署。

## 保存与升级

统一工具默认寻找同级 `MisakaNetwork` 项目，也可通过 `--project <项目根目录>` 指定。三家分别写入 `LastOrder/assets/cloud_templates/tencent.json`、`aliyun.json`、`volcengine.json`，保持原有版本冲突检查及原子保存。云厂商选择只切换编辑页面，不会把一家的配置写到另一家文件。

已有管理员资产在本轮保持原内容，只升级模板版本并明确填写原先使用的登录账号。以后导入旧格式时需重新生成，不保留旧格式兼容分支。保存新模板后必须重新构建完整 LastOrder 应用；独立网页或源码修改不会自动更新已安装应用。

早期开发版云记录中的旧模板快照不自动迁移。升级前先在原应用停止任务，核对并释放不再使用的实例，处理未确认资源；不要通过删除本地资料来停止计费。新格式无法读取旧快照时阻止继续云操作并保留资料。需保留的远端资源先在云控制台核对和安排管理方式，再切换应用；不承诺旧记录可直接重用。

本轮没有升级项目版本号或构建发行安装包，也未变更 biliTickerBuy 源码、依赖、导入白名单或执行参数。镜像选择范围变化不放宽项目既有运行时安全约束。

## 验证范围

本轮对三家镜像查询、模板生成与解析、SSH 账号传递、已知非 Linux/不兼容架构拒绝，以及统一网页的厂商切换和保存隔离补充离线回归。

- Go 全量 race 测试和 vet 通过，Windows x64 辅助程序交叉编译通过。
- Flutter 静态检查通过，全量测试 793 项通过、2 项可选截图测试因未设置截图环境变量跳过。随后追加三家旧快照缺少 `sshUsername` 的保护回归，相关模板测试共 12 项通过，验证初始化失败、原始工作区不被覆盖、不继续云 API 操作。
- Python 运行时 88 项测试执行通过（其中 5 项因可选依赖缺失跳过），发行与打包脚本 110 项通过。

- 独立网页 56 项 Python、30 项 JavaScript 测试通过。浏览器检查首页三厂商跳转、完整镜像选项、操作系统与 SSH 账号填写、三家分别保存，以及 390px 窄屏布局；页面无横向溢出，控制台无警告或错误。保存检查使用临时项目，未写入真实模板；预览服务已关闭。

上述结果为源码、模拟响应和本机浏览器验证，没有使用真实凭据购买、释放或验证不同发行版的完整云部署与费用，也没有构建本轮发行安装包。
