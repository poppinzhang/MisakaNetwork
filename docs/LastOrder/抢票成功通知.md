# LastOrder 抢票成功通知（0.5.0 起）

在右上角「配置」打开「抢票成功通知」。该设置仅在当前 LastOrder 生效，初始为关闭。Android 和 macOS 在用户主动开启时请求系统权限。Windows 直接使用系统通知区域。系统的勿扰模式、通知权限和展示选项决定提醒能否打扰用户。

## 哪些结果会通知

Sisters 只在运行时正常返回最终 `succeeded` 时将 `TaskStatus.order_created` 设为真。LastOrder 收到成功终态和该标记、且能关联本机任务和账号时，才向系统提交通知。已创建订单可能仍需付款，用户应到哔哩哔哩核对。

| 机器回报 | 系统通知 |
| --- | --- |
| 本次成功创建订单 | 提醒一次，缺少付款码也可提醒 |
| 检测到已有订单（`duplicate_order`） | 静默，监控页面仍可展示已有订单 |
| 排队、等待开售、进度、失败、取消、结果未知或断开连接 | 静默 |
| 旧节点成功终态但缺少新订单标记 | 静默，等现有任务结束后重新部署 Sisters 可启用新标记 |

## 投递与去重

LastOrder 从提交、取消和状态同步回复中处理同一份结构化结果。取得合法订单号时按账号 UID 和订单号合并多台机器的回报。缺少合法订单号时按机器与执行 ID 去重。本地配置仅保存开关和已观察结果的派生标识。系统通知使用固定标题和正文，内容不含任务名、账号、购票人、订单号、付款码或链接。

已观察的结果与任务结束确认一起持久化，再交给系统。这样重复刷新、重新打开应用或重新开启通知都不会重播已观察的订单。系统拒绝投递时，仅在「配置」内显示原因。若应用在记录成功后、提交给系统前意外退出，该条通知可能漏发，用户仍可在「任务监控」核对。

| 平台 | 本机通知方式 |
| --- | --- |
| Android | 系统「抢票成功」通知渠道。可在系统设置内调整声音、横幅和锁屏显示 |
| macOS | 系统通知中心，应用在前台时也支持展示 |
| Windows | Windows 通知区域，由系统处理提示，点击可返回 LastOrder |

通知来自 LastOrder 收到的 Sisters 回报。应用退出或节点离线时，提醒须等应用恢复同步且节点仍保有结果。控制端沿用现有 mTLS 连接。

## Android 切后台与锁屏

开启「抢票成功通知」且有分发任务等待结果时，LastOrder 在应用仍可见时启动 `dataSync` 前台服务。按 Home、切换应用或锁屏后，同一 Flutter 引擎继续使用已有的五秒轮询、订单判定和去重记录。暂时失联的任务仍可在连接恢复后核对。任务全部结束或关闭开关时自动停止服务。

系统要求前台服务显示运行状态。LastOrder 使用单独的「后台任务监控」渠道显示「正在监控抢票结果」，默认无声、无振动。点这条状态可以回到应用。新订单仍通过「抢票成功」渠道提醒，两条渠道可分别在系统设置中调整。

Android 对后台数据同步前台服务有时限。应用在后台运行时，24 小时内累计可用 6 小时，重新回到前台会重置时限。达到时限后，LastOrder 会按系统要求停止服务。若提前很久分发了定时任务，临近开售时可再打开一次 LastOrder。深度休眠还可能暂停网络，清除最近任务、强行停止应用或系统回收进程也会中断监控。再次打开 LastOrder 时会立即查询，并根据未结束任务恢复监控。[Android 前台服务时限](https://developer.android.com/develop/background-work/services/fgs/timeout) · [Android 休眠与网络限制](https://developer.android.com/training/monitoring-device-state/doze-standby)

## 验证范围

Go 竞态测试覆盖最终结果、已有订单和取消后补报成功。Flutter 回归覆盖权限拒绝、开关与外观保存、重复轮询、并发回报、重启去重及写入失败后恢复。Android 16 arm64 模拟器上使用合成结果验证了原生权限和通知投递。macOS 调试构建及原生通道的无效请求测试通过。Windows 主机通知展示、macOS 实际横幅和真实业务订单尚待验证。

后台监控已在 Android 16 arm64 模拟器分别验证切到桌面和熄屏两种场景。同一 Flutter 引擎在 Activity 暂停后完成两轮轮询，处理模拟新订单并投递一条系统成功通知，最后移除监控服务。原生测试另外覆盖了拒绝权限、快速启停、清除最近任务、系统时限到期及返回前台恢复。尚未验证真机长时间深度休眠、厂商省电策略或真实订单。

Android 后台集成用例使用独立模拟器、本地模拟任务和真实系统通知。在测试应用中预先允许通知，再从 LastOrder 目录运行以下命令（将设备 ID 替换为当前测试模拟器）。出现「正在监控抢票结果」后按 Home，保持在桌面。用例会在退到后台后的第二轮状态查询回报新订单，可在系统通知栏核对成功提醒和监控状态移除。

```sh
flutter test --dart-define=MISAKA_TEST_BACKGROUND_MONITOR=true \
  integration_test/android_background_monitor_test.dart -d emulator-5554
```
