# LastOrder 0.1.0

本文记录 0.1.0 基础功能并补充后续操作变化；0.1.1 的账号状态检查、失效清理、重新登录与新存储模型见 [Cookie 生命周期](Cookie生命周期.md)。文中的 0.1.0 平台限制仅描述历史版本，当前平台能力见 [Windows 与 Android](Windows与Android.md)，安装包与升级操作见 [0.2.3 交付记录](../releases/0.2.3.md)。

LastOrder 是 MisakaNetwork 的 Flutter 桌面管理端。本版本交付 macOS 客户端，最低 macOS 15.0，界面与测试统一使用官方 `material_ui` Material 3 组件；Lucide 提供图标，`flutter_animate` 用于日常动效，`animations` 3.x 用于页面切换。

## 功能流程

1. **机器管理**：录入 Linux/macOS 主机的 SSH 信息，确认 SHA-256 主机公钥指纹，由内置 `misakactl` 部署匹配系统与架构的 Sisters 及 biliTickerBuy。重新部署保留同一连接标识并沿用原指纹，不接受静默更换公钥。SSH 密码和私钥口令仅在本次部署的内存中使用，不保存到机器元数据；私钥通过系统文件选择器读取。以上为已交付流程；源码未发布的后台部署、临时副本清理和首次自动保存指纹行为见下节。没有外部程序下载步骤。部署结果带有 `reachable` 字段，表示本机能否直接以 mTLS 连上 `地址:gRPC 端口`（部署器经隧道健康检查通过后再测一次）；为 `false` 时机器仍会保存，并提示确认防火墙或安全组已放行该 TCP 端口。
2. **已部署机器接入**：开启“连接已部署的 Sisters”，选择 CA、客户端证书、客户端私钥，并填写服务地址与证书服务端名称。证书通过系统文件选择器授予读取权限后复制到应用私有目录，避免依赖长期外部文件访问授权。
3. **账号登录**：0.3.1 起使用哔哩哔哩手机客户端扫码自动检测登录（0.3.0 及更早安装包需扫码后点击“检测登录”），或导入已有的 Cookie JSON 数组并验证；自动检测流程见下节。二维码仅在内存中展示。历史 macOS 版本将账号 Cookie 逐条存入登录钥匙串（login Keychain），0.3.0 起的存储方式见 [macOS 加密存储](macOS加密存储.md)。
4. **创建任务**：按演出 ID 或会员购链接读取真实场次、票档、购票人和收货地址。日历场次可填写日期。选择票档与一个或多个购票人，填写联系人及电话。沿用 biliTickerBuy 0.1.0 适配约束，电子票也必须选择收货地址；缺失时提示在平台补齐后重新读取。任务配置通过上游构建与校验后加密保存。开售时间（北京时间）默认取所选票档的起售时间，可修改，留空则分发后立即开始；它保存在普通元数据中，分发时随任务发送，且只发给声明支持开售时间的 Sisters。
5. **分发任务**：选择一台或多台 Sisters，确认后发起真实任务。不同机器分发彼此独立，部分失败明确列出；相同机器可以接收多个不同任务，Sisters 决定排队与并发。已交付的 0.2.3 对同一任务、同一机器保留永久提交保护，重新运行需创建新任务；源码未发布的修复允许在确认执行结束后再次分发，并为新一轮生成独立执行 ID，详见下文。
6. **任务监控**：每五秒同步已保存机器的状态与事件，支持手动刷新和停止指定机器上的指定任务。连接失败时保留最后一次记录，并明确标记过期风险。删除本地任务或移除机器不会假定远程任务已停止。

## 扫码自动检测

打开“登录哔哩哔哩”或“重新登录账号”窗口后自动生成二维码，并在等待扫码或手机确认期间自动查询状态，不再显示“生成二维码”主按钮或“检测登录”按钮。正常情况下每次单次查询完成后等待 2 秒再查询，同一会话只保留一个在途查询；实际响应时间还取决于网络及 Android 运行时排队。账号列表的“检查登录”和手动 Cookie 验证入口保留。

只有平台明确返回二维码失效才停止并提示重新生成，不按本地 180 秒计时强制过期。运行时明确返回可恢复的临时异常时，连续第一次失败等待 4 秒、第二次等待 8 秒后重试，第三次暂停并提供“重试连接”；重试沿用同一二维码，让平台判断是否仍有效。安装、原生桥接超时、异常协议等未知错误停止自动检查并提示重新生成，避免底层可能仍在途时继续排入请求；异常响应不会冒充过期。点击“重新生成二维码”会直接生成新码并继续自动检查。

确认成功后仍须验证新 Cookie 的账号身份，重新登录必须为原 UID；成功保存后自动关闭窗口。若身份已验证但本地保存失败，结果仅暂存内存并提供“重试保存”，不重新轮询领取 Cookie；关闭、切换登录方式或重新生成会清除待保存结果。

前后台切换暂停与恢复新请求，不丢弃当前会话已收到的成功结果；该结果只暂存内存，回前台后继续处理。关闭、切换已有 Cookie 或重新生成时废弃旧会话，迟到响应不能再保存或改变新窗口。检查期间不因普通轮询禁用关闭操作；用户结束会话后不再调度新请求，底层已在途调用可能仍会完成。

扫码与已有账号例行巡检协调：活动扫码会话期间暂缓新的例行巡检，结束后只补做延后且已到期的账号；刚验证有效的当前凭据不立即重复检查。手动检查、读取场次和分发前的校验保持执行。旧凭据迟到检查仍受凭据版本与检查序号保护，不能覆盖或删除新 Cookie；详见 [Cookie 生命周期](Cookie生命周期.md#扫码自动检测与例行检查协调)。该行为随 0.3.1 全平台包交付（0.3.0 及更早版本仍按原按钮检测流程），但不代表真实扫码或原生设备后台行为已验收。

## macOS 单一主密钥加密存储（未发布）

macOS 的 `StateStore` 将账号 Cookie、含购票人信息的任务配置、云凭据及云部署密钥写入本地 AES-256-GCM 加密文件，登录钥匙串只保存一个应用主密钥。首次访问合并为同一个解锁操作，同一会话复用密钥，后续账号检查、任务分发和云记录保存不再逐条读取钥匙串。密文损坏、密钥缺失及拒绝授权时明确失败并保留文件，不静默重置。Windows/Android 的直接系统安全存储路径不变。

本次不兼容历史 macOS 资料，使用独立根目录保存元数据、密文、PKI 和导入凭据；旧文件、旧钥匙串条目不会迁移或清理。切换前先处理远端任务并核对旧云资源，之后重新添加/部署机器、登录账号、创建任务、录入云凭据和设置偏好。完整格式、并发与错误语义、验证范围见 [macOS 加密存储](macOS加密存储.md)。此为源码未发布改动，不改变 0.2.3 的实际安装包和签名状态。

## 执行结束与重新分发（未发布）

原分发窗口使用永久 `dispatchedTo` 历史记录禁选机器，将「曾经提交」误当成「仍在执行」，取消或成功后也无法再次选择。现在按机器的最新执行判断是否可分发：`SUCCEEDED`、`FAILED`、`CANCELLED` 确认后释放未结束计数；排队、运行和结果未确认仍保持禁选。任务卡片显示未结束或待确认的机器数量，历史执行不占用该数量。

`TicketTask.dispatches` 保存 `TaskDispatch(machineId, executionId, finished)`，仅包含关联标识和结束确认，不保存 Cookie、购票人或付款内容。首轮执行 ID 为任务配置 ID，此后每次主动分发使用新 UUID，避免 Sisters 将重新执行当作旧请求返回历史结果。监控与付款展示按机器和执行 ID 历史关联原任务，取消仍只针对选中的一轮执行；新一轮不会覆盖旧结果。旧 `dispatchedTo` 读取为首轮待确认记录，不要求重新登录或重建配置；能从节点取得终态时补记结束，无法确认的旧记录仍需先核对远端任务与订单，再决定是否新建任务。

分发前验证账号、机器状态与节点能力，在串行保存中重新核对最新执行并持久化意图，保存失败不发送请求；同一任务与机器的并发分发被阻止。只有确定尚未发送或收到明确拒绝时才撤销本轮意图；网络异常、响应丢失、应用退出或远端历史缺失都不能证明执行结束，保持待确认且不自动重发。轮询及提交、取消响应会补记结束确认，取消返回的终态立即更新缓存，旧轮询中的运行状态不能覆盖它。

已成功的任务再次分发仍会启动真实抢票，界面提醒先核对订单。已有执行使用原提交凭据，新一轮按分发前的账号校验读取当前凭据；不会热更新其他节点或其他轮次。此修复未改协议、Sisters 调度、biliTickerBuy 运行参数或已交付版本，也未进行真实下单验证。

本轮源码验证：`flutter analyze --no-pub` 通过，`flutter test --no-pub` 共 368 项通过，1 项可选云预览截图测试因未配置截图字体与输出参数按既有条件跳过。回归涵盖终态后重新分发与新执行 ID、未知状态保护、并发提交与持久化失败、取消和旧轮询竞争、已确认订单不被迟到取消覆盖、负载与禁选更新，以及多轮监控和付款关联；明确拒绝与网络失败的分类另由本机 gRPC 模拟服务验证。验证使用模拟账号与节点，不代表安装包、真实登录或抢票业务验收。

## 清除已结束的监控记录（未发布）

「任务监控」对成功、失败和取消（`SUCCEEDED`、`FAILED`、`CANCELLED`）的执行卡片提供单条「清除」，并提供「清除全部已结束任务」按钮，后者仅处理点击时当前显示的已结束记录；没有待清记录时禁用。排队、执行中或状态未知的记录保留。清除标记保存成功后才移除卡片，保存失败时卡片保留并提示重试。

批量操作捕获点击时的记录快照，全部标记通过一次本地保存写入，失败时不部分隐藏。等待保存期间状态改变的记录、后来新出现的完成记录留待下一次核对，不会把补报成功或新一轮执行一并清除。

清除标记以机器 ID、执行 ID 和当时的终态为键，保存在普通元数据中，不复制任务配置、Cookie、订单号或付款内容。后续轮询和重开应用不会重新显示匹配记录；新的执行 ID 不受旧标记影响。若已清除的取消记录后来收到成功结果，因为终态发生变化会重新显示，避免漏看订单。

清除只过滤执行卡片，不删除账号、任务配置、分发账本或 Sisters 远端历史，不调用取消或删除 RPC，也不改变幂等保护和重新分发条件。监控页上方的订单和付款入口仍按完整回报保留，用户可继续核对与付款。

此功能尚未打包发布。本轮 `flutter analyze --no-pub` 通过，`flutter test --no-pub` 全量 393 项通过，1 项可选云预览截图测试按既有条件跳过。清除功能的回归覆盖单条与跨机器批量清除、运行中与未知状态保留、单次保存与失败后无部分隐藏、并发点击去重、保存等待期间的状态变化、重开及轮询保持隐藏、新执行与迟到成功重新显示、订单入口保留及窄屏大字体操作；不代表真实业务或发行包验收。

## 付款码回显与订单详情（未发布）

「任务监控」增加订单展示，提供「查看付款二维码」与「打开订单详情」。按本地任务关联的账号 UID 和订单号聚合相同订单，合并来源节点与任务，不以任务名称或单一任务 ID 判断同一订单；不同账号、不同订单保持分开。找不到本地任务或账号关联时不展示具体支付入口，原任务状态仍可查看。重复五秒轮询只更新数据，不自动弹出付款窗口，也不自动取消其他机器。

客户端重新校验订单号与支付内容，详情链接由合法订单号生成固定官方 HTTPS 地址。二维码使用 `payment_code_url` 内容，通过本机内嵌运行时的 `payment_qr` 在内存生成 PNG；不请求支付网站，不将上游的 `payment_qr_url` 误当作付款码。生成失败或无合法支付内容时仍保留订单详情入口，打开浏览器失败提供可恢复提示；浏览器可能需要重新登录相同账号。手机使用同一订单入口完成核对，不要求扫描自身屏幕。

订单和二维码只随当前状态保留在内存，不写入 `SavedState` 或普通日志。应用重开后可从仍保留结果的节点重新取得；节点重启、重新部署、历史淘汰或本地关联移除后可能无法展示。连接失败保留的记录可能已过期，获取时间不表示有效期。此版不刷新付款码、不查询支付状态，也不根据显示二维码推断付款或出票。协议、严格白名单、安全复核与验证范围见[付款码回显](../付款码回显.md)。

## 抢票请求间隔与下单尝试（未发布）

创建任务表单新增「抢票请求间隔（毫秒）」，默认 `1000`，只接受 `100`–`60000` 的整数；空值、非整数与越界输入会提示修改，不保存任务。间隔以 `TicketTask.requestIntervalMs` 保存到普通任务元数据，任务卡片展示对应毫秒数，更新分发记录与重启后保留；未记录该字段的任务按默认 `1000` 毫秒读取。此字段不包含账号或购票人信息，完整购票配置继续保存在安全存储。

分发时使用已保存任务的间隔，通过 `TaskRequest.request_interval_ms` 交给 Sisters，再写入内嵌运行时的 `runtime_options.interval`。每次提交前实时检查目标节点的 `supports_request_interval`；未声明支持时不提交，并提示重新部署。定时任务继续检查 `supports_time_start`。Sisters 校验范围并将实际采用的间隔计入幂等摘要，同一任务 ID 携带不同间隔会被拒绝。

每轮下单尝试上限由内嵌运行时固定为 `40`，不显示可编辑字段，也不接受 `create_retry_limit` 运行参数覆盖。达到每轮上限后可能继续下一轮，不代表整个任务只尝试 40 次；请求之间的实际时间还受响应耗时与上游冷却逻辑影响。间隔需要在创建任务时确定，修改需创建新任务，已分发执行不会热更新。

源码测试覆盖输入与范围校验、默认值、保存/读取和分发记录更新、请求参数传递及旧节点拒绝；Sisters 与运行时另覆盖有效间隔的幂等去重、固定 40 次和禁止覆盖。测试使用虚构账号、模拟响应与离线引擎，不代表真实登录、下单、出票或所有平台发行包验收。此改动尚未打包发布；使用包含改动的完整应用时，先停止或等待已有任务结束，再重新部署所有 Sisters。

## 腾讯云实例部署（未发布）

腾讯云实例卡片从「已创建 · 待部署」进入「部署 Sisters」流程，使用应用创建服务器时的 SSH 身份与当前 Ubuntu 镜像的默认 `ubuntu` 账号，无需选择或导出私钥。发起前刷新精确实例状态与公网地址，保存关联的待部署机器，再复用下文的首次指纹保存、后台进度、离线包、自检和 mTLS 连接保存流程。部署成功后，该机器才可进入任务分发。云资源与节点共用原云服务器卡片，部署进度、失败原因、连接状态、版本和运行时信息在该卡片内展示，重试、重新部署和移除本地连接也在同一卡片操作；关联机器不再额外生成一张普通卡片。此调整不删除底层机器或任务历史，找不到云记录的连接仍以普通卡片保留。

云服务器卡片隐藏地域名称及代码、可用区和实例 ID，保留规格、计费状态、公网地址、部署和节点状态；底层资源标识仍用于查询、恢复和精确释放。底部操作使用统一尺寸与间距，宽度充足时等宽双列排列，窄屏及大字体转为单列，避免按钮按文字长度错位。

释放后，只有查询确认精确实例已终止，或已提交释放的已知实例确实不存在时，才自动从机器管理移除该云卡及关联节点，无需再点删除。已释放节点不计入当前机器总数或分发候选，重启后也不回显；释放请求受理、查询失败和结果未知时继续显示原卡片。底层云确认记录与机器保持关联，已有任务、监控和付款结果继续可核对，不因卡片移除而清除；共享网络、安全组和公钥仍保留。

## 后台部署与进度（未发布）

点击「安全部署」后先校验表单、预留机器标识并保存本地记录，随后关闭「添加 Sisters」窗口。SSH 连接、离线包传输、自检及服务启动由控制器继续执行；用户可留在机器列表查看各台进度，也可继续添加其他机器。每台卡片独立显示「部署 Sisters」、估算百分比、进度条与当前步骤，不使用全局等待窗口阻止后续操作。重新部署使用同一机器 ID；地址不变时沿用已保存的 SSH 指纹，修改地址则按新主机首次连接处理。

新部署在发起网络操作前检查名称与地址，忽略 SSH/gRPC 端口差异；不同名称不能绕过相同地址限制。地址比较规范化 IPv4、IPv6 及 IPv4 映射 IPv6，并忽略主机名大小写和末尾点；不通过 DNS 查询把不同域名合并为同一机器。发起部署时同步预留名称与地址，覆盖本地保存尚未结束的并发提交，避免重复请求同时通过校验。已有机器需使用原卡片的重新部署或重试入口。

首次 SSH 连接只探测主机指纹，控制器接收 helper 的 `needs_confirmation` 响应后自动校验格式并持久化，再携带该固定指纹重新调用部署。机器卡片持续显示后台进度，不再出现指纹核对窗口、等待确认阶段或对应取消按钮。首次指纹保存失败时不发起后续部署；已保存指纹的连接不得再次自动接受新指纹，异常或重复探测响应须停止，避免无限重试。重试与重新部署沿用已保存指纹，主机公钥变化时失败。

这是首次使用时信任（TOFU），只能检查保存后的身份连续性，不等于经管理员或云助手独立确认首次所见服务器的真实性；不会关闭 SSH 固定指纹校验，也不改变 gRPC 双向 TLS。部署不提供会跳过检查与回滚的中断按钮。

百分比依据安装包发送字节数和部署阶段的固定权重估算，不表示剩余时间。连接、环境检查、传包、写入配置、自检、激活和健康检查分别更新进度；失败不会显示为完成。结果成功且本地连接资料保存完成后，机器恢复普通在线/连接状态展示；远程自检通过但本机直连失败时保留连接，并说明防火墙或安全组检查方法。

| 估算进度 | 依据 |
| --- | --- |
| 2%–15% | 准备部署、建立 SSH、检查系统和离线包、准备安全配置 |
| 20%–75% | 送入 SSH 上传流的压缩包字节数占文件总大小的比例；解压由远程命令完成 |
| 78%–86% | 写入安全配置、Sisters 自检和内嵌抢票运行时自检 |
| 90%–97% | 启动服务、经隧道验证安全连接、检查本机直连 |
| 100% | helper 返回成功且控制器保存连接资料完成 |

每个部署请求在受保护的独立随机临时目录中持有一份进度快照，Go helper 以原子替换写入，Flutter `LocalHelper` 定期读取并在请求结束后清理。快照仅包含预定义阶段和整数百分比，不含地址、用户名、凭据、路径或远端原始输出；读取端限制大小、校验字段及阶段白名单，忽略倒退或损坏的快照。进度写入失败不打断远程激活与回滚，最终成功仍由 helper 终态响应决定；读取到的 100% 不能提前覆盖失败，控制器在本地保存完成前最多显示 99%。桌面辅助进程和 Android JNI 使用同一机制，Android 另外限制进度文件位于应用私有目录。

控制端首次 PKI 初始化在各后台部署之间共享同一个 Future，生成完成后才允许多个 helper 并行读取证书，避免初次并发部署产生冲突。Android 部署 helper 使用可并行执行的线程池；运行时调用和离线资源准备仍保留各自的串行执行器。

待部署机器以 `Machine.deploymentPending` 保存；出错信息以 `deploymentError` 保存，密码、私钥口令和敏感请求参数不写入元数据。失败保留机器和错误，可从「重试部署」重新填写本次 SSH 凭据，不生成重复记录。应用重启后把尚未结束的部署标为中断并提示核查远程状态，不自动恢复部署。部署中与尚未完成部署的机器跳过状态轮询并禁止分发；旧轮询回包不能覆盖新部署状态。

提交表单后，控制器接管本次导入的 SSH 私钥副本，直到成功或失败才清理。其他机器保存或删除时不会清理仍被部署任务使用的文件；文件选择期间也持有导入保护，避免并发部署完成时误删尚未提交的副本。启动时清理上次应用被结束后遗留且不再被保存机器引用的文件。关闭添加窗口不会清空仍在运行的部署所需凭据；部署结束后释放请求中的敏感字段。

### 监控消息跟随（未发布）

`TaskMessages` 用紧凑的消息区替代完整事件文本。默认只显示最新一条；存在多条消息时提供「展开消息」，展开后按先后顺序显示最近 3 条，最新一条位于底部。新回报到来时自动淘汰最旧一条并向上更新，无嵌套滚动区、手动日志翻页或页面自动跳转；消息正文自然换行。系统关闭动效时直接更新内容。收起后恢复只显示最新回报，展开状态通过包含机器 ID 与任务 ID 的存储键独立保留。

消息来自 Sisters 已有的白名单 `TaskStatus.message` 与 `events`，不改变服务协议、日志回传或运行参数。实时状态可能在阶段事件上补充倒计时和尝试次数：状态与末条事件时间相同时，用更完整的当前状态覆盖该条事件，避免相同阶段重复展示；状态消息为空时回退到最近事件。无消息时显示「等待执行信息」，不伪造执行进度。

消息仅合并相邻的相同正文，保留「执行 → 重试 → 执行」这样的阶段往返；只有时间变化时更新显示时间，不重复播放动效。`task_messages_test.dart` 的 13 项测试覆盖最新消息选择、倒计时合并、最近三条前移、展开状态隔离、重复刷新与减少动效；更新后的任务布局测试另覆盖双列等高、窄屏、摘要精简、切页恢复、无内部滚动和新消息不改变页面滚动位置。

## 安全与错误处理

macOS App Sandbox 保持开启，授予客户端联网和用户选择文件的只读权限。普通 JSON 只保存机器信息、证书路径、SSH 指纹、账号名称以及任务关联元数据；Cookie 和含购票人信息的完整任务配置均不以明文进入普通文件。应用目录与凭据目录权限为 0700，元数据与证书副本为 0600。源码未发布的加密文件也使用 0600 权限，本地登录钥匙串仅保存主密钥；既有发行版仍逐条保存敏感资料。本地签名分发不申请共享钥匙串组，也不需要用户具备 Apple 开发者签名身份；重新签名或更新可能触发系统访问确认，单一主密钥不等于在所有系统状态下保证只弹一次。普通状态先写临时文件再原子替换；读取失败会保留原文件并阻止继续写入。

TLS 信任范围限定为配置的 CA，并提供客户端证书与私钥；不会放行不受信任的证书或禁用主机名验证。网络连接有超时：TCP 连接最多 8 秒，每次调用 12 秒截止；同一连接配置复用一个 mTLS 通道，轮询不必每次重新握手，空闲 5 分钟后由 gRPC 断开连接。轮询不重入，任务提交错误与单机状态错误分别呈现。相同名称的机器不能重复添加，确保部分失败反馈可以准确定位。名称在部署之前检查，冲突时不会连接 SSH，也不会重启远端服务和中断其上的任务。

`misakactl` 及 `misaka-runtime` 从应用 `Contents/Resources/` 启动；敏感 JSON 通过标准输入管道传递，不放入命令行参数或日志。运行时 stdout 限制为 8 MiB，桥接调用 90 秒超时；部署请求最多等待 30 分钟（各阶段由 helper 自行限时），其余 helper 请求 300 秒超时。退出码非零、协议缺少终态、超时（包括子进程不读取 stdin）、权限失败均视为失败；SSH 首次指纹探测作为独立响应处理，由控制器保存后自动继续。普通应用退出时会终止本地桥接与部署辅助进程；不会自动取消已提交到远端 Sisters 的任务。部署进行中退出时会先弹窗确认：中断部署会跳过健康检查与回滚，远端可能停在未验证的新版本或已停止，默认选项是继续等待。系统强制结束进程不能保证清理回调执行。

## 公有云凭证与交互预览（未发布）

「公有云部署」导航及「机器管理 → 公有云凭证」进入凭证管理；「添加机器 → 云服务器创建&部署」提供厂商选择、缺失凭证跳转和三套示例配置选择。腾讯云使用 SecretId/SecretKey，阿里云使用 AccessKey ID/AccessKey Secret，火山引擎使用 Access Key ID/Secret Access Key；只提供两项访问密钥输入，不再提供账号备注；本地格式检查后调用官方只读身份接口联网验证，通过后才保存。每厂商仅保留一份，已验证状态隐藏全部输入框和提交按钮，控制器拒绝直接覆盖；只有成功移除后才显示空白表单。验证失败保留旧的未验证记录，移除失败继续保留已保存状态。旧的仅格式检查记录需重新提交验证，三家的创建或预览入口只接受已联网验证凭证；仍有未释放或待核实资源时保留删除与更换 SecretId 保护。联网验证不代表资源操作权限、余额或库存已就绪。其他厂商保留等待接入空状态。详细调研依据见[公有云接入方案](公有云接入方案.md)。

界面采用 Material 3 与 Lucide，宽屏为厂商列表与表单双栏，手机改为紧凑厂商选项；模板宽屏三列、窄屏单列。相关单元与控件测试见 `cloud_controller_test.dart`、`cloud_ui_test.dart`；`cloud_preview_capture_test.dart` 是按环境变量启用的真实控件截图检查，常规测试默认跳过。截图使用模拟凭据与登录密钥，不是实账号或发布安装包验收。
