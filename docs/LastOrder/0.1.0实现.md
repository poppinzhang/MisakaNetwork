# LastOrder 0.1.0

本文记录 0.1.0 基础功能并补充后续操作变化；0.1.1 的账号状态检查、失效清理、重新登录与新存储模型见 [Cookie 生命周期](Cookie生命周期.md)。文中的 0.1.0 平台限制仅描述历史版本，当前平台能力见 [Windows 与 Android](Windows与Android.md)，安装包与升级操作见 [0.2.3 交付记录](../releases/0.2.3.md)。

LastOrder 是 MisakaNetwork 的 Flutter 桌面管理端。本版本交付 macOS 客户端，最低 macOS 15.0，界面与测试统一使用官方 `material_ui` Material 3 组件；Lucide 提供图标，`flutter_animate` 用于日常动效，`animations` 3.x 用于页面切换。

## 功能流程

1. **机器管理**：录入 Linux/macOS 主机的 SSH 信息，确认 SHA-256 主机公钥指纹，由内置 `misakactl` 部署匹配系统与架构的 Sisters 及 biliTickerBuy。重新部署保留同一连接标识并沿用原指纹，不接受静默更换公钥。SSH 密码和私钥口令仅在本次部署的内存中使用，不保存到机器元数据；私钥通过系统文件选择器读取。源码未发布的后台部署流程、临时副本清理和指纹确认入口见下节。没有外部程序下载步骤。部署结果带有 `reachable` 字段，表示本机能否直接以 mTLS 连上 `地址:gRPC 端口`（部署器经隧道健康检查通过后再测一次）；为 `false` 时机器仍会保存，并提示确认防火墙或安全组已放行该 TCP 端口。
2. **已部署机器接入**：开启“连接已部署的 Sisters”，选择 CA、客户端证书、客户端私钥，并填写服务地址与证书服务端名称。证书通过系统文件选择器授予读取权限后复制到应用私有目录，避免依赖长期外部文件访问授权。
3. **账号登录**：使用哔哩哔哩手机客户端扫码后点击“检测登录”，或导入已有的 Cookie JSON 数组并验证。二维码仅在内存中展示。账号 Cookie 存入 macOS 登录钥匙串（login Keychain），由系统加密和应用访问控制保护。
4. **创建任务**：按演出 ID 或会员购链接读取真实场次、票档、购票人和收货地址。日历场次可填写日期。选择票档与一个或多个购票人，填写联系人及电话。沿用 biliTickerBuy 0.1.0 适配约束，电子票也必须选择收货地址；缺失时提示在平台补齐后重新读取。任务配置通过上游构建与校验后存入钥匙串。开售时间（北京时间）默认取所选票档的起售时间，可修改，留空则分发后立即开始；它保存在普通元数据中，分发时随任务发送，且只发给声明支持开售时间的 Sisters。
5. **分发任务**：选择一台或多台 Sisters，确认后发起真实任务。不同机器分发彼此独立，部分失败明确列出；每个任务对同一台机器只提交一次：本地元数据记录已接收该任务的机器（轮询时在远端发现的同 ID 任务也会补记），分发窗口将这些机器标为已提交，不再重复提交，Sisters 重启后也不会重复执行；未记录前的重试使用相同任务 ID，由 Sisters 保证幂等。若远端任务已结束，界面明确提示本次未重新执行，要再次执行应创建新任务。相同机器可以接收多个不同任务，Sisters 决定排队与并发。
6. **任务监控**：每五秒同步已保存机器的状态与事件，支持手动刷新和停止指定机器上的指定任务。连接失败时保留最后一次记录，并明确标记过期风险。删除本地任务或移除机器不会假定远程任务已停止。

## 后台部署与进度（未发布）

点击「安全部署」后先校验表单、预留机器标识并保存本地记录，随后关闭「添加 Sisters」窗口。SSH 连接、离线包传输、自检及服务启动由控制器继续执行；用户可留在机器列表查看各台进度，也可继续添加其他机器。每台卡片独立显示「部署 Sisters」、估算百分比、进度条与当前步骤，不使用全局等待窗口阻止后续操作。重新部署使用同一机器 ID；地址不变时沿用已确认的 SSH 指纹，修改地址则重新核对新主机。

新部署在发起网络操作前检查名称与地址，忽略 SSH/gRPC 端口差异；不同名称不能绕过相同地址限制。地址比较规范化 IPv4、IPv6 及 IPv4 映射 IPv6，并忽略主机名大小写和末尾点；不通过 DNS 查询把不同域名合并为同一机器。发起部署时同步预留名称与地址，覆盖本地保存尚未结束的并发提交，避免重复请求同时通过校验。已有机器需使用原卡片的重新部署或重试入口。

首次 SSH 连接只取得主机指纹，机器卡片转为「等待确认 SSH 主机指纹」。用户点击「核对 SSH 指纹」，与管理员提供的 SHA-256 指纹核对，再点击「指纹一致，部署」后才继续；关闭核对窗口只返回列表，不自动认可指纹。卡片的「取消部署」只用于尚未确认指纹的阶段，保留可重试的失败记录；已开始传包或激活的部署不提供会跳过检查与回滚的中断按钮。

百分比依据安装包发送字节数和部署阶段的固定权重估算，不表示剩余时间。连接、环境检查、传包、写入配置、自检、激活和健康检查分别更新进度；失败不会显示为完成。结果成功且本地连接资料保存完成后，机器恢复普通在线/连接状态展示；远程自检通过但本机直连失败时保留连接，并说明防火墙或安全组检查方法。

| 估算进度 | 依据 |
| --- | --- |
| 2%–15% | 准备部署、建立 SSH、检查系统和离线包、准备安全配置 |
| 20%–75% | 送入 SSH 上传流的压缩包字节数占文件总大小的比例；解压由远程命令完成 |
| 78%–86% | 写入安全配置、Sisters 自检和内嵌抢票运行时自检 |
| 90%–97% | 启动服务、经隧道验证安全连接、检查本机直连 |
| 100% | helper 返回成功且控制器保存连接资料完成 |

每个部署请求在受保护的独立随机临时目录中持有一份进度快照，Go helper 以原子替换写入，Flutter `LocalHelper` 定期读取并在请求结束后清理。快照仅包含预定义阶段和整数百分比，不含地址、用户名、凭据、路径或远端原始输出；读取端限制大小、校验字段及阶段白名单，忽略倒退或损坏的快照。进度写入失败不打断远程激活与回滚，最终成功仍由 helper 终态响应决定；读取到的 100% 不能提前覆盖失败，控制器在本地保存完成前最多显示 99%。桌面辅助进程和 Android JNI 使用同一机制，Android 另外限制进度文件位于应用私有目录。

控制端首次 PKI 初始化在各后台部署之间共享同一个 Future，生成完成后才允许多个 helper 并行读取证书，避免初次并发部署产生冲突。Android 部署 helper 使用可并行执行的线程池；运行时调用和离线资源准备仍保留各自的串行执行器。

待部署机器以 `Machine.deploymentPending` 保存；出错信息以 `deploymentError` 保存，密码、私钥口令和待确认的请求参数不写入元数据。失败保留机器和错误，可从「重试部署」重新填写本次 SSH 凭据，不生成重复记录。应用重启后把尚未结束的部署标为中断并提示核查远程状态，不恢复部署、不自动确认指纹。部署中与尚未完成部署的机器跳过状态轮询并禁止分发；旧轮询回包不能覆盖新部署状态。

提交表单后，控制器接管本次导入的 SSH 私钥副本，直到成功、失败或用户拒绝指纹才清理。其他机器保存或删除时不会清理仍被部署任务使用的文件；文件选择期间也持有导入保护，避免并发部署完成时误删尚未提交的副本。启动时清理上次应用被结束后遗留且不再被保存机器引用的文件。关闭添加窗口不会清空仍在运行的部署所需凭据；部署结束后释放请求中的敏感字段。

### 监控消息跟随（未发布）

`TaskMessages` 用紧凑的消息区替代完整事件文本。默认只显示最新一条；存在多条消息时提供「展开消息」，展开后按先后顺序显示最近 3 条，最新一条位于底部。新回报到来时自动淘汰最旧一条并向上更新，无嵌套滚动区、手动日志翻页或页面自动跳转；消息正文自然换行。系统关闭动效时直接更新内容。收起后恢复只显示最新回报，展开状态通过包含机器 ID 与任务 ID 的存储键独立保留。

消息来自 Sisters 已有的白名单 `TaskStatus.message` 与 `events`，不改变服务协议、日志回传或运行参数。实时状态可能在阶段事件上补充倒计时和尝试次数：状态与末条事件时间相同时，用更完整的当前状态覆盖该条事件，避免相同阶段重复展示；状态消息为空时回退到最近事件。无消息时显示「等待执行信息」，不伪造执行进度。

消息仅合并相邻的相同正文，保留「执行 → 重试 → 执行」这样的阶段往返；只有时间变化时更新显示时间，不重复播放动效。`task_messages_test.dart` 的 13 项测试覆盖最新消息选择、倒计时合并、最近三条前移、展开状态隔离、重复刷新与减少动效；更新后的任务布局测试另覆盖双列等高、窄屏、摘要精简、切页恢复、无内部滚动和新消息不改变页面滚动位置。

## 分发负载与多任务风险（未发布）

分发窗口按服务器列出当前任务数量、任务名称及状态。负载依据 Sisters 状态中的执行中和排队中任务，执行中包含等待开售；已成功、失败或停止的任务不计入当前负载。即使本地已删除任务，只要 Sisters 仍报告其未结束，就继续展示。未知远端状态保守显示为「状态待确认」。任务名称优先使用远端名称，缺失时回退到本地名称或任务 ID。

打开窗口时刷新服务器状态，窗口随每五秒轮询更新，也可点击「刷新负载」。提交前再次等待刷新完成；若已有查询进行中，共享该轮查询并等待结果及分发记录保存结束。连接失败时保留最近状态并标记「负载未更新」，首次未获取状态则标记「负载未知」，不将无记录显示为服务器空闲。仅在状态缺失或连接失败时，把本地已提交但远端记录中没有的任务补为「状态待确认」；成功查询后的空列表不会被历史提交记录误判为仍有任务，缓存中已结束的任务也不会被重新补入。

选中仍承担其他任务的服务器后，立即显示「多任务风险」，说明同一服务器承担多个抢票任务容易触发购票网站风控。提交前弹窗列明受影响服务器及已有任务，默认聚焦「返回选择」，只有点击「仍然分发」才继续。负载未确认的服务器也需要确认，并明确说明无法排除多任务风险。返回选择保留勾选，取消或关闭窗口不提交任务；确认期间轮询发现新的风险服务器或任务时，再次列明新增风险并确认。当前任务已提交的服务器继续禁选，已结束任务不触发多任务提示。

提示依据查询时可见的任务状态，不能保证其他控制端不会在之后提交新任务，也不保证避免平台风控。Sisters 的排队、并发和跨机器独立执行语义保持原有约定。本次为源码未发布改动，没有变更项目版本、协议、账号存储或 biliTickerBuy 运行参数；0.2.3 安装包尚不包含此功能。

回归覆盖 `machine_workload_test.dart`、`refresh_test.dart`、`dispatch_dialog_test.dart` 及原有主界面分发流程，使用模拟服务器与账号，不发起真实登录或订单。

本次本地源码验证：`flutter analyze --no-pub` 无问题，工作区 `flutter test --no-pub` 全部 208 项通过，其中新增负载判断 8 项、共享刷新 3 项、分发界面 12 项。界面回归包含 320 像素窄屏、两倍字体、浅色与深色、刷新期间关闭及确认期间新增风险。未重新打包、执行远程 CI 或进行真实抢票业务验收。

## 代码结构

- `LastOrder/lib/src/app.dart`：管理台及机器、登录、任务表单；宽屏侧栏与紧凑桌面布局。
- `LastOrder/lib/src/task_messages.dart`：监控卡片的最新消息、最近三条回报与自动更新动效。
- `LastOrder/lib/src/about_dialog.dart`：可滚动的关于窗口、项目简介、外链与名称来由。
- `LastOrder/lib/src/open_source_licenses.dart`：离线第三方许可加载、注册与查看。
- `LastOrder/lib/src/app_info.dart`：关于窗口使用的应用版本与构建号。
- `LastOrder/lib/src/dispatch_dialog.dart`：分发机器选择、负载展示及多任务风险确认。
- `LastOrder/lib/src/machine_workload.dart`：当前任务投影、离线状态回退与风险判断。
- `LastOrder/lib/src/controller.dart`：状态流转、持久化协调、任务分发与取消、定时轮询。

- `LastOrder/lib/src/models.dart`：可序列化的元数据模型及用户可读错误。
- `LastOrder/lib/generated/`：由公共 protobuf 生成的 Dart gRPC 客户端，不手工修改。

## 安全与错误处理

macOS App Sandbox 保持开启，授予客户端联网和用户选择文件的只读权限。普通 JSON 只保存机器信息、证书路径、SSH 指纹、账号名称以及任务关联元数据；Cookie 和含购票人信息的完整任务配置均不进入普通文件。应用目录与凭据目录权限为 0700，元数据与证书副本为 0600。本地签名分发使用 macOS login Keychain，不申请共享钥匙串组，也不需要用户具备 Apple 开发者签名身份；重新签名或更新可能触发系统访问确认。普通状态先写临时文件再原子替换；读取失败会保留原文件并阻止继续写入。

TLS 信任范围限定为配置的 CA，并提供客户端证书与私钥；不会放行不受信任的证书或禁用主机名验证。网络连接有超时：TCP 连接最多 8 秒，每次调用 12 秒截止；同一连接配置复用一个 mTLS 通道，轮询不必每次重新握手，空闲 5 分钟后由 gRPC 断开连接。轮询不重入，任务提交错误与单机状态错误分别呈现。相同名称的机器不能重复添加，确保部分失败反馈可以准确定位。名称在部署之前检查，冲突时不会连接 SSH，也不会重启远端服务和中断其上的任务。

`misakactl` 及 `misaka-runtime` 从应用 `Contents/Resources/` 启动；敏感 JSON 通过标准输入管道传递，不放入命令行参数或日志。运行时 stdout 限制为 8 MiB，桥接调用 90 秒超时；部署请求最多等待 30 分钟（各阶段由 helper 自行限时），其余 helper 请求 300 秒超时。退出码非零、协议缺少终态、超时（包括子进程不读取 stdin）、权限失败均视为失败；SSH 指纹确认作为独立响应处理。普通应用退出时会终止本地桥接与部署辅助进程；不会自动取消已提交到远端 Sisters 的任务。部署进行中退出时会先弹窗确认：中断部署会跳过健康检查与回滚，远端可能停在未验证的新版本或已停止，默认选项是继续等待。系统强制结束进程不能保证清理回调执行。

## 公有云凭证与交互预览（未发布）

「公有云部署」导航及「机器管理 → 公有云凭证」进入凭证管理；「添加机器 → 云服务器创建&部署」提供厂商选择、缺失凭证跳转和三套示例配置选择。腾讯云使用 SecretId/SecretKey，阿里云使用 AccessKey ID/AccessKey Secret，火山引擎使用 Access Key ID/Secret Access Key；支持账号备注和本地格式检查，不能据此声称云端身份或权限有效。其他厂商保留等待接入空状态。详细调研依据见[公有云接入方案](公有云接入方案.md)。

`CloudController` 独立管理凭证和预览节点，通过 `StateStore` 的系统安全存储持久化，不把云密钥、SSH 私钥写入普通配置。`AppController` 启动后异步初始化，云存储或密钥准备失败不阻断既有机器功能。Go 辅助动作 `generate_cloud_ssh_key` 只在内存生成 RSA 2048/OpenSSH 公钥、PEM 私钥和 SHA-256 登录指纹；桌面和 Android 共用同一实现。私钥和公钥作为一个安全存储条目保存，后续启动复用，不静默覆盖损坏条目。

每台预览节点保存模板快照，确认后立即回到机器管理；独立计时推进创建、部署与完成，可选择创建失败、部署失败预览。释放有确认窗口，失败/完成记录可删除。中途退出后标记预览已中断，不自动继续。所有写入串行执行，存储失败不显示成功；背景阶段保存失败时保留可读错误。云预览节点没有真实 IP、云资源 ID 或 mTLS 材料，不加入 `SavedState.machines`，不参与五秒查询、抢票任务分发或 SSH 部署。此轮不联网验证凭证、不上传公钥、不调用创建/释放 API，也不计费。

界面采用 Material 3 与 Lucide，宽屏为厂商列表与表单双栏，手机改为紧凑厂商选项；模板宽屏三列、窄屏单列。相关单元与控件测试见 `cloud_controller_test.dart`、`cloud_ui_test.dart`；`cloud_preview_capture_test.dart` 是按环境变量启用的真实控件截图检查，常规测试默认跳过。截图使用模拟凭据与登录密钥，不是实账号或发布安装包验收。
