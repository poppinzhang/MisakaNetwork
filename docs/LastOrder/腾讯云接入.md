# 腾讯云 CVM 基本流程（未发布）

本轮实现腾讯云普通按量计费实例的共享 VPC/子网准备、安全组准备、公钥导入、创建、查询、Sisters 部署与释放。源码功能尚未发布，不代表现有 0.2.3 安装包已经支持，也不代表真实账号权限、云资源、费用或抢票业务已验收。阿里云与火山引擎的资源创建/释放仍是本地交互预览，三家凭证提交均会联网验证身份。

## 使用流程与边界

1. 管理员填写 `LastOrder/assets/cloud_templates/tencent.json` 后重新构建完整应用。仓库默认是空模板集合，腾讯云页面不会提供虚假的可购买配置。
2. 在「公有云部署」提交腾讯云 SecretId、SecretKey，应用调用官方只读身份接口验证成功后才保存。每家厂商仅保存一份，不填写账号备注。保存成功后隐藏所有输入框和提交按钮；需要更换时必须先成功移除当前凭证，再填写新密钥。旧的仅格式检查记录仍可重新提交验证，成功后才能创建实例；验证失败不保存新输入。该检查不创建资源，也不代表已具备后续资源操作权限、余额或库存。
3. 从「添加机器 → 云服务器创建 → 腾讯云」选择已打包模板，核对地域、建议可用区、规格、系统盘及固定登录与网络规则，确认创建按量实例。SSH 用户固定为 Ubuntu 镜像默认的 `ubuntu`，使用密钥登录；SSH TCP 22 和 Sisters TCP 20001 均允许所有 IPv4 来源（`0.0.0.0/0`）。余额、配额、库存与实际价格以腾讯云为准。
4. LastOrder 先保存操作意图，自动准备目标地域的共享 VPC、目标可用区的子网、安全组和 SSH 公钥，保存实际资源 ID 后提交购买请求，明确售罄时按下述规则回退至同地域其他可用区，受理后轮询云端状态。无需在模板中填写网络 ID。实例运行后显示「已创建 · 待部署」、规格及公网地址；机器卡片不展示地域名称及代码、可用区或实例 ID。
5. 点击云实例卡片的「部署 Sisters」。应用重新核对实例运行状态与公网地址后，读取创建时使用的内置 SSH 身份，以 `ubuntu` 连接 TCP 22；首次主机指纹自动保存后继续安装离线包、启动 Sisters 并保存 mTLS 连接。部署成功后才允许分发任务，失败可从原云服务器卡片重试；部署进度、错误和节点状态也显示在这张卡片内。
6. 需要停止使用时，从该实例卡片确认「释放云服务器」。释放会中断服务器上的任务并销毁系统盘数据；后续查询确认实例已终止，或确认已提交释放的精确实例不存在后，自动移除该云服务器卡片及关联节点，无需再次手动删除。请求仅受理、查询失败或结果待核实时保留卡片。关闭应用不释放资源、不保证停止计费；额外关联资源和账单仍需在云平台核对。

云实例部署复用首次自动保存 SSH 主机指纹、后续固定指纹验证、离线部署、linger 检查和 mTLS 可达性验证，也不改动 biliTickerBuy 运行时。创建完成或应用重启不会擅自开始 SSH 部署；此前已创建且仍保留完整云记录的实例也可使用同一入口。

## 模板与打包

固定入口为 `LastOrder/assets/cloud_templates/tencent.json`，顶层格式为 `{"schemaVersion":3,"templates":[]}`。字段、限制与脱敏示例见[模板目录说明](../../LastOrder/assets/cloud_templates/README.md)。支持多套模板，模板 ID 必须唯一；读取失败时禁止创建，不回退到演示配置。格式 1/2 不再接受，管理员需用新版填写工具重新生成模板并重新打包；没有旧格式兼容分支。

早期开发版保存的格式 1/2 云记录含不再接受的旧模板快照，不自动迁移。仍使用这些格式的实例，需先在对应旧版核对并释放、移除已确认释放的旧云记录，再切换到格式 3；结果未知的记录应保留用于核对。已经采用格式 3 的云记录不受该模板升级要求影响，本轮修复 SSH 账号与卡片展示无需重新购买实例。已交付 0.2.3 尚无真实腾讯云记录，不受此项影响。读取到不支持的旧记录时停止云操作，不覆盖安全存储。

模板指定地域、建议可用区、实例类型、公共 Ubuntu 24.04 镜像、x64/arm64、系统盘及按流量后付费公网带宽。CPU、内存是管理员维护的展示信息，须与实际机型一致。创建前还会核对镜像的系统、架构、状态与最小系统盘大小。VPC 和子网由运行层准备，SSH 用户和端口来源由程序固定；模板严格拒绝 `sshUsername`、`sshCidr`、`grpcCidr`、`VirtualPrivateCloud`、`VpcId`、`SubnetId`，也不保存云凭据或 SSH 私钥，不接受任意 API 参数、启动脚本、额外数据盘、竞价、包年包月或独立 EIP。

购买层固定 `InstanceChargeType=POSTPAID_BY_HOUR`、`InstanceCount=1`，应用生成登录密钥、安全组、操作标签和幂等 token；这些字段不能由模板覆盖。模板公网方式固定为 `TRAFFIC_POSTPAID_BY_HOUR`，不设置预付费公网带宽。

资源已在 `pubspec.yaml` 声明，标准 Flutter assets 构建会将 JSON 打进 Windows、macOS、Android；完整应用仍须按[打包与发布](../打包与发布.md)构建。替换模板后必须重新打包，已创建实例保留当时模板快照。不要将个人网络 ID、地址、账号环境信息或凭据提交进公共仓库；管理员的实际模板仅用于所需的本地构建。

管理员填写网页是仓库外的独立本地工具，不属于 LastOrder、不进入源码或发布包。本机服务只接受来自自身页面的操作，将校验后的整个模板集合原子保存到上述固定文件，不提供任意路径写入。

填写工具提供联动选项。地域/可用区首先使用官方文档参考快照（标明核查日期和特殊售卖说明，不表示账号当前可购买）；用户可在网页临时输入 SecretId/SecretKey，再主动查询实时地域、可用区、按量可售机型及兼容 Ubuntu 24.04 官方镜像。选择机型带回 CPU/内存，选择镜像带回架构与最小系统盘容量；切换上游配置会清理依赖选项。也保留手工填写入口和每个字段的官方说明。网页不再提供 VPC/子网 ID 字段或网络查询，不创建网络资源；真正创建发生在 LastOrder 的云服务器准备流程中。

机型代码按官方返回值保留大小写。[官方实例规格](https://cloud.tencent.com/document/product/213/11518) 包含 `S5se.LARGE16`、`S9pro.MEDIUM4` 等混合大小写的实例族；查询响应、镜像查询入参、模板保存及 Go/Dart 模板解析采用一致格式，不能将机型限制为全大写或自动转成大写。加载按钮旁显示前置条件错误、查询状态和空列表；镜像查询需要先选中机型，标识格式异常会指出对应资源类别，不回显原始响应。

管理员查询工具仅允许固定的 Describe 接口，不包含购买、创建网络或释放接口。密钥通过本机页面送到本机服务，服务对固定腾讯云 HTTPS 端点签名查询；密钥不写模板、普通文件或日志，不读取 LastOrder 安全存储。刷新页面或主动清除临时凭据后需重新输入；云端权限不足、网络失败与真实空列表分别提示。网页查询结果是查询时点的参考，不能保证后续购买时仍有库存或余额。

| 字段 | 含义与官方查询方式 |
| --- | --- |
| 地域 / 可用区 | 地域是地理区域；可用区是区域内独立机房。参考[地域和可用区](https://cloud.tencent.com/document/product/213/6091)，实时查询采用地域管理系统的 [DescribeRegions](https://cloud.tencent.com/document/product/1596/77930) / [DescribeZones](https://cloud.tencent.com/document/product/1596/77929)，产品固定为 CVM。 |
| 机型 | 不是固定通用枚举。按可用区与 `POSTPAID_BY_HOUR` 查询 [DescribeZoneInstanceConfigInfos](https://cloud.tencent.com/document/api/213/17378)，只展示接口报告可售的规格。 |
| 镜像 ID | 指具体系统镜像；按地域与选定机型查询 [DescribeImages](https://cloud.tencent.com/document/api/213/15715)，再筛选正常状态的 Ubuntu 24.04 官方公共镜像。 |
| VPC / 子网 | 无需填写，由 LastOrder 使用所选地域/可用区自动创建或复用共享网络，实际 ID 保存于运行时资源记录。 |

工具额外需要 `region:DescribeRegions`、`region:DescribeZones`、`cvm:DescribeZoneInstanceConfigInfos`、`cvm:DescribeImages` 的查询权限。其中机型可售查询也是 LastOrder 自动切换可用区需要的权限，不构成额外购买授权；实际授权资源范围以腾讯云当前 CAM 文档为准。

## 同地域可用区回退

模板的 `runInstances.Placement.Zone` 是建议值，首先按该区准备网络并购买。仅在 `RunInstances` 明确返回容量或库存不足、该区不售卖机型或不支持该可用区，且能够确认请求被拒绝时，才通过 helper 的 `tencent_zones` 操作调用 [DescribeZoneInstanceConfigInfos](https://cloud.tencent.com/document/api/213/17378)，在模板地域内查询候选区。候选项必须保持完全相同的 `InstanceType`，计费方式为 `POSTPAID_BY_HOUR`，并报告 `Status=SELL`；过滤重复项及已尝试可用区，每个候选区最多购买一次。可售查询只是当时库存参考，不保证后续购买成功。

回退保持地域、机型、架构、镜像、系统盘规格、网络带宽、单实例数量、登录公钥、安全组及计费方式不变；仅切换 `Placement.Zone` 和该区对应子网。VPC 仍按地域共享，切换前通过既有共享网络账本创建或复用目标区子网。原模板快照保留建议可用区，机器记录另存选定可用区；创建确认窗口说明回退规则，选定可用区继续保存在资源记录中，机器卡片不展示可用区。

每次切换使用新的购买 token，并在发出购买请求前持久化选定可用区、子网和本次意图；相同 token 不用于不同可用区的请求。明确拒绝必须保存成功后才能开始下一区，保存失败即停止。所有候选区都明确售罄时停止并保留失败原因；候选查询失败、无候选区、网络准备失败，以及余额、配额、权限或其他参数错误也停止，不借换区反复购买。

超时、连接中断、响应丢失、内部错误等不能证明购买未发生的结果，均停止回退并进入查询恢复；查询暂时没有实例也不能触发新购买。应用退出或重启不会自动继续购买。此前因售罄尝试而准备的共享子网会保留，不随实例释放。

## 自动共享网络

同一云账号、同一地域复用专用 `MisakaNetwork-VPC`，IPv4 网段固定为 `10.8.0.0/16`。同一 VPC、同一可用区复用 `MisakaNetwork-Subnet-<可用区>`；首次创建从 VPC 中选择未与已有子网重叠的 `/24` 网段。使用腾讯云默认路由表，不创建 NAT 网关、独立 EIP、VPN 或额外网络服务。

名称用于查找，归属必须同时通过 `misaka-managed=lastorder-v1`、`misaka-network=shared-v1` 标签及名称、网段、VPC 和可用区核验。名称查询可能是模糊匹配，适配器会精确过滤并分页核对；同名但归属或配置不匹配、多个匹配资源、子网地址不足等情况停止准备，不接管、改名或删除用户已有网络。购买前再次核验实际 VPC/子网。

网络准备采用独立的查询和创建动作。创建请求返回不等于资源立即可用；查询暂未看见新 VPC/子网时，界面保持准备状态并在有界窗口内轮询，不立即把首次查无结果当作创建失败。每个网络最多查询 30 次，查询之间等待 2 秒（最多 58 秒等待，另加请求耗时）；应用退出即停止后续查询。LastOrder 在系统安全存储中维护不依赖单台服务器记录的共享网络账本，每次网络创建前保存意图，提交购买前保存实际网络 ID。明确拒绝允许下次重新查询与准备；超时、响应丢失或应用中断导致的未知结果只查询恢复，查询暂时没有结果不能作为重复创建依据。删除失败机器记录或释放云服务器均保留共享网络账本。

尚未提交服务器购买的失败记录提供「重试准备并创建」，仍按上述账本查询确认；已经提交购买的记录继续使用实例查询恢复，不重新购买。网络创建响应中已知的合法 ID 会以待核实状态保存，后续轮询固定核对该资源；即使随后查询失败也不会切换到同名的其他资源。轮询只查询，不重新发送创建请求；超时后保留待核实账本，用户重试仍先查询，未确认前禁止服务器购买。确认结果保存失败时停止后续购买，在内存保留已知 ID；跨重启只能保证此前已保存的待核实意图仍阻止重复创建，不能保证未成功写入的 ID 已落盘。

本应用内串行准备可以避免自身并发争抢，但固定名称和管理标签不是跨客户端的云端锁；多个独立客户端同时首次创建时仍可能产生重复资源，发现歧义后停止并提示管理员核对。本轮不提供网络删除或未知意图重置入口。共享 VPC/子网不随单台 CVM 释放，即使本机已无其他实例也不会据此自动删除。

官方依据：[CreateVpc](https://cloud.tencent.com/document/api/215/15774)、[CreateSubnet](https://cloud.tencent.com/document/api/215/15782)、[DescribeVpcs](https://cloud.tencent.com/document/api/215/15778)、[DescribeSubnets](https://cloud.tencent.com/document/api/215/15784)。创建接口没有可直接使用的 `ClientToken` 参数，不能将名称复用视为服务端幂等保证。

## 安全组、公钥与通信

安全组使用固定项目前缀和固定规则摘要形成稳定名称，按地域查询并复用，不随模板变化。这些接口以资源 ID 或对象返回，不假定存在统一的异步任务 ID，而是通过对应的 Describe 接口确认资源可见和配置就绪。新安全组、导入公钥及新增安全组规则均等待查询确认后再进入下一步；暂不可见或规则尚未生效时有界轮询，权限、归属或规则冲突不作为等待成功处理。公钥、安全组可见性及每个规则方向的等待上限均为 30 秒，查询间隔 1 秒，并受 helper 整体 3 分钟和取消信号约束。轮询不重复提交创建或规则变更请求。安全组出站 `ALL` 请求省略 `Port`，按官方参数约束发送；读取时接受空端口或 `all` 的等价表达。入站 TCP 22 与 TCP 20001 的来源均固定为 `0.0.0.0/0`，出站允许正常联网。填写网页和创建确认界面展示固定规则，不提供来源输入项。相同名称的组必须符合本项目归属和预期策略，不静默改写已有组；此前按其他来源生成的安全组不会被原地扩大规则，已有服务器也不会自动变更。应用内串行准备以减少重复创建；多个独立客户端同时首次创建仍受云端接口的并发语义约束，不能承诺全账号唯一。

首次启动生成的 RSA 2048 SSH 身份继续保存在系统安全存储；只把公钥导入腾讯云，按公钥内容生成稳定名称并核对已有公钥，不上传私钥。安全组、登录公钥、VPC 和子网是复用资源，释放单个实例不删除它们。

当前模板只接受 Ubuntu 24.04 官方镜像，部署登录用户固定为 `ubuntu`，不由模板指定。腾讯云[官方 SSH 登录说明](https://cloud.tencent.com/document/product/213/35700)将 Ubuntu 默认用户列为 `ubuntu`，并给出该用户的密钥登录示例；此前固定 `root` 与当前镜像类型不一致，本轮予以纠正。创建实例仍仅通过 `LoginSettings.KeyIds` 绑定原公钥，不传密码、用户名或初始化脚本；不自动开启 root 登录、不改写 sshd 或 authorized_keys，也不轮流尝试其他账号。此结论来自源码与官方说明，没有证明用户实际服务器的登录配置或密钥状态，真实登录仍需验证。

腾讯云 API 在控制端 Go helper 中调用：桌面使用标准输入辅助进程，Android 复用原生桥接。不使用环境变量、命令行参数或普通文件传递密钥，不将管理云资源的权限交给 Sisters。固定腾讯云 HTTPS 域名、保留证书链和域名校验、禁止跟随重定向；TC3 签名由封闭的标准库适配器实现，不增加云 SDK 依赖。上游原始错误消息和请求体不进入界面或日志。

## 内置密钥部署与机器关联

「部署 Sisters」只对已取得实例 ID 的真实腾讯云记录开放。点击后重新查询精确实例，核验项目归属、操作标识、运行状态和可用公网地址；未运行、释放中、已释放或查询失败均不能开始 SSH。部署默认使用 `ubuntu`、SSH TCP 22 和 Sisters TCP 20001，不从模板接受额外 SSH 参数。

部署账号以 `Machine.deploymentUsername` 随待部署及成功的机器记录保存。重试沿用 `ubuntu`；已知曾使用其他账号的连接，或旧版未记账号且不能确认在登录前停止的连接，均拒绝直接切换账号部署，防止旧账号服务仍运行时又启动另一份 Sisters。旧版未记录账号、没有节点证书，且明确因认证失败或未确认指纹而停止的记录可以原地重试，沿用实例、机器 ID 和已确认指纹，无需重新购买。其他旧连接须先由管理员停止旧账号下的 Sisters 并核对任务，再移除本地连接、从同一云卡片部署；应用不会自动迁移或清理旧服务，移除本地连接也不会停止服务。

应用从系统安全存储读取原 SSH 身份，并核对当前公钥与指纹。私钥通过桌面 helper 的标准输入或 Android 原生桥接交给 Go，在内存中解析为 SSH 签名器；不导出到临时文件、命令行、环境变量、普通机器状态或日志。仍有未确认释放的已提交购买记录而 SSH 身份丢失时，不会自动生成替代密钥，需先恢复原身份或核对云端资源；只有已确认释放的历史记录时，不阻止后续准备新身份。

云记录与本地 Sisters 机器使用稳定关联，机器 ID 由 `tencent-<云记录 ID>` 确定并随普通机器元数据保存，重启后保持关联。首次部署先保存待部署机器，再执行 SSH；失败重试继续使用同一机器和已保存指纹，避免再次点击新增重复机器。原地址已属于其他记录时停止，不能静默覆盖既有连接。已关联机器的公网地址发生变化时也停止，需先核对云端，再移除旧本机连接记录后重新部署；这一步不释放云服务器。首次连接采用首次使用时信任（TOFU），自动保存 SHA-256 主机指纹后继续；保存失败或已知指纹不匹配时停止。此方式不提供首次连接的独立主机身份认证，后续验证及 gRPC 双向 TLS 不变。关联机器存在时，部署进度、持久化部署错误、gRPC 连接地址、在线或等待状态、版本、并发上限和运行时就绪信息全部显示在原云服务器卡片；列表不再为同一资源额外绘制普通机器卡片。云记录缺失时仍显示独立连接卡片供核对，避免丢失操作入口。合并仅改变展示，不删除底层机器、任务分发或历史记录。卡片继续提供重试、重新部署和「移除连接」；移除仅清理本地连接，不释放实例、不停止远端服务。

云卡片不展示地域名称及代码、可用区或实例 ID；这些字段仍保存在资源记录中，用于对账、恢复和精确释放。底部操作按钮等宽等高、间距一致，宽度充足时为两列，窄屏与大字体切换单列；部署、查询、释放和移除连接各自的可用条件及确认范围不因布局改变。

从准备部署到成功或失败，云记录保持部署占用，禁止并行部署和释放；自动保存首次指纹期间也保持该保护。应用退出不停止云计费，也不会在下次启动时自动继续 SSH。重新部署会结束远端任务，仍需先停止或等待已有任务结束。关联云记录丢失、释放中、已释放或地址不匹配时，普通机器连接不能继续轮询、分发或发送停止请求。云端释放与本机记录清理是不同操作，不能用删除本地机器代替释放云服务器。

Linux 部署先检查当前账号的 linger，再按既有规则尝试 `loginctl enable-linger`。此云端 `ubuntu` 内置密钥路径通过 `enable_linger_with_sudo` 显式允许一条受限补救命令：`sudo -n loginctl enable-linger ubuntu`；只有前述尝试后仍未开启才执行，并重新查询当前账号状态。该选项不接受其他用户名、密码或文件私钥，不使用 sudo shell，不请求密码，不改变 SSH 登录策略，也不把 Sisters 改成 root 服务。权限不足或复查失败时停止上传并提示管理员处理；普通 SSH 部署保持原有不提权行为。

SSH 握手失败分别归类为指纹不匹配、认证拒绝、超时或其他握手失败，显示经过限定的提示而非服务端原始错误。认证拒绝应核对默认账号及创建时绑定的原密钥，不能通过跳过指纹检查解决；握手类失败不能据此判定私钥错误。

## 状态持久化与异常恢复

云账号与资源记录保存在独立系统安全存储条目；持久化地域、创建时 SecretId 关联、模板快照、操作 UUID、每次可用区尝试的独立 ClientToken、选定可用区及已尝试记录、安全组/公钥 ID、实例 ID、云端请求 ID 与进度。未释放或创建结果待核实的实例阻止删除本地记录、移除凭据或换成其他 SecretId。网络创建意图尚未确认时也禁止移除凭证或更换 SecretId。每厂商仅有一份凭证；已联网验证的凭证禁止直接覆盖，即使沿用同一 SecretId 更新 SecretKey，也必须先满足资源保护条件并成功移除。旧的未验证记录可以重新提交验证，仍须保留资源对应的 SecretId。移除成功后删除本地保存的该份凭证，不撤销云端密钥、不释放资源，也不删除资源记录。

购买前先保存请求意图。创建响应丢失时显示「创建结果待核实」，查询按操作标签找回精确实例；该次尝试不重新调用 RunInstances，不自动换 token 或可用区再次购买。查询没有结果不能证明没有创建，仍须在腾讯云控制台核对。创建准备失败、且确认未提交购买的记录可以移除；准备阶段已生成的共享组和公钥会保留以供复用。

应用重启恢复查询，不重新购买、不自动销毁。释放请求仅针对本地记录的精确实例，并核验项目标签、操作 token 与按量计费类型。额外数据盘、独立 EIP 等超出本轮管理范围的资源会阻止自动释放，交由用户在控制台处理；不会因为关联到实例就擅自删除。释放 API 返回请求 ID 只是受理，查询失败、超时或权限不足均保留记录与费用提示。

查询已核验的实例返回 `TERMINATED`，或已提交释放的已知实例查询确认不存在时，持久化状态为 `released`。机器管理自动移除该云卡及关联的 Sisters 卡片，当前机器总数和分发候选也排除该节点；重启读取确认状态后保持移除。底层云确认记录和关联机器仍保留供任务历史、监控及付款信息关联，不调用删除机器的清理流程，也不把最近一次任务结果改写为成功或取消。共享 VPC、子网、安全组和公钥继续保留。未确认的购买响应查询为空不属于释放成功，不能触发卡片移除。

只有释放确认状态成功保存后才移除卡片；安全存储写入失败时保留「释放待核实」卡片和错误，修复存储后可再次刷新查询，不提前隐藏，也不重新提交释放请求。

实例 ID 返回后本地保存失败时，在内存保留 ID 和错误；重启依靠此前已持久化的 token 查询恢复。没有实例 ID 的未知记录无法直接销毁，须先找回实例或去控制台核实。自动查询最多 60 轮，每轮查询结束后间隔 5 秒（不含请求耗时），之后转为人工刷新；Android 后台或应用退出不保证持续查询。
